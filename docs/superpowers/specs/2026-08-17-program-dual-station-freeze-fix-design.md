# 程序管理双工位卡顿修复设计

## 目标

修复双工位模式下程序管理页新增、删除、批量清理和刷新可能导致 WinForms 无响应的问题，同时消除保存路径中仍存在的 UI 线程同步数据库操作。

## 根因范围

- 工位 2 配方名称读取按 `RecipeCount` 逐槽串行读取，配置没有数量上限，异常地址或慢 PLC 会延长刷新窗口。
- 程序管理页会在保存、删除和批量清理后的 UI 绑定中重复 `Clear`/`AddRange` 两个配方下拉框；双工位时工位 2 列表已填充，重复控件刷新成本明显增加。
- 页面启动的配方刷新未绑定页面生命周期取消，PLC 读取返回时可能与用户操作后的控件绑定交错。
- `SaveWithSyncDecisionAsync`、`GetNextSequenceNumber` 和部分 `ReloadPrograms` 路径仍在 UI 线程同步访问数据库。

## 设计

- 每工位最多允许 64 个配方槽位；配置校验和读取入口均拒绝超限配置。
- 配方刷新使用页面取消令牌，每工位总时限 10 秒；读取结果完成后统一按刷新版本更新 UI，取消或超时保留已有选择并显示失败状态。
- 配方选择器只在选项集合实际变化时重建 Items；设置选中值不再重复重建列表。
- 程序保存、另存为序号查询、删除和批量清理统一使用后台数据库操作与程序变更串行门；列表刷新统一使用异步查询。
- 不改变 MES 字段、同步状态、PLC 工位配方映射和程序历史版本语义。

## 验证

- 增加配方数量上限、超时/取消、双工位选择器不重复重建和程序保存异步路径回归检查。
- 串行运行控制台回归 harness。
- 使用 `artifacts/verify-bin/` 隔离目录构建解决方案。
- 现场仍需验证正常 PLC、工位 2 地址错误/断线、MySQL 慢设备和双工位人工 UI 操作。
