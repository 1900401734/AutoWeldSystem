# MES 完工上报工时精度设计

## 目标

完工上报的 `WorkHour` 字段保留两位小数，MES 收到的工时字面量始终是两位形式。

## 范围

- 新增 `AutoWeldSystem.Core/Mes/MesWorkHourRules`，统一工时的舍入与定标。
- 替换三处完工请求的工时计算：在线完工即时请求、离线完工写入补传 payload、补传前对缺失工时的重算。
- 不修改 `ExperimentEndReq` DTO：该文件为 GB2312 编码，改动有整文件中文注释乱码风险，且定标由构造方保证已足够。
- 不改写数据库中已入库的历史补传 payload。
- 不调整开工上报、工单状态上报和过程参数上报的字段。

## 设计选择

**定标而非仅舍入。** `decimal` 自带标度，`JsonSerializer` 按标度原样输出，因此 `Math.Round(1m, 2)` 序列化后是 `1` 而不是 `1.00`。规则在舍入后加上 `0.00m` 把标度固定为两位。这行加法容易被误认为冗余代码，已在源码中注释说明原因。

**四舍五入而非银行家舍入。** 显式传入 `MidpointRounding.AwayFromZero`。工时是给现场和对账看的时长，不是需要统计无偏的金额；.NET 默认的 `ToEven` 会把 `1.005` 变成 `1.00`，现场核对时无法解释。

**不覆盖历史 payload。** 离线完工请求序列化后持久化，规则只作用于本次改动之后新产生的完工上报。队列中已存在的未定标工时（大于 0）原样透传，不做数据迁移。

**短任务接受 0.00。** 不足 0.01 小时（约 18 秒）的任务上报 `0.00`，不设非零下限。`0.00` 是舍入的真实结果，抬升为 `0.01` 等于向 MES 写入伪造数据；出现极短工单应在现场排查，不应被舍入规则掩盖。

**补传兜底分支同步纳入规则。** `UploadTaskService` 原有 `WorkHour <= 0` 时重算的兜底逻辑，而定标后的短任务工时正好是 `0.00`，会命中该分支。若只改构造点，18 秒以内的任务会绕过定标把长小数发给 MES，因此该分支的重算也走同一规则。
