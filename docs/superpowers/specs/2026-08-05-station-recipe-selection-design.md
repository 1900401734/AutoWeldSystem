# 双工位 PLC 配方名称隐式关联设计

## 背景

当前 PLC 配方号由程序管理界面直接显示和保存。双工位设备的左右工位分别维护独立的 PLC 配方槽位，同一产品对应的配方号可能不同，也可能只存在于其中一个工位。例如同一产品在工位 1 的配方号可能为 `2`，在工位 2 的配方号可能为 `5`。如果双工位同工单继续复用同一个手工配方号，可能向其中一个工位下发错误配方。

地址维护界面的“配方名称地址”页签已经按工位读取 PLC 配方名称，并通过基地址、配方数量和固定偏移建立槽位关系：槽位顺序即实际数字配方号。PLC 配方名称由现场人员手工填写，可能不规范、可能变化，也可能无法输入部分字符，因此名称只能供用户辨认，不能作为运行时匹配键。

本设计继续以数字配方号作为 PLC 下发和校验的唯一准确值，但将数字对普通业务用户封装起来。程序管理只展示各工位读取到的配方名称；用户选择名称时，系统隐式保存该选项携带的配方号，并在运行时按目标工位下发。

## 目标

- 程序管理分别提供工位 1、工位 2 的配方名称下拉选择。
- 用户只看到 PLC 配方名称，不看到也不能手工输入数字配方号。
- 下拉选项内部保留地址维护映射得到的工位号和配方号。
- 继续使用 `RecipeCode` 保存工位 1 配方号，使用 `Station2RecipeCode` 保存工位 2 配方号。
- 双工位同工单时，同一个程序按目标工位分别下发各自的隐藏配方号。
- 双工位双工单时，程序只在已配置配方关联的工位可用。
- 程序列表直接移除“配方编号”列，不增加替代列。
- 生产监控和在线/离线开工等业务界面不再显示或手工选择配方号。
- 地址维护映射页和日志诊断继续允许显示实际配方号。
- MES 程序创建、更新、下载和同步契约保持不变。

## 非目标

- 不新增程序—工位—配方映射表，不修改数据库结构。
- 不将 PLC 配方名称写入程序实体，也不以产品工号或配方名称作为下发匹配键。
- 不在每次下发前通过名称动态重新查找配方号。
- 不处理同一工位重复配方名称；正常流程按用户实际选择的选项保存其隐藏配方号。
- 不实现单个配方名称地址失败、其他地址成功时的部分降级策略。
- 不自动迁移 PLC 槽位顺序或名称变化后的历史关联。
- 不扩展到两个以上工位。
- 不修改 MES 请求、响应、同步状态或程序上下行字段。

## 核心数据模型

### 地址维护映射

`PlcRecipeNameReaderService` 继续按工位读取名称。`PlcRecipeNameRules.BuildOptions` 按配置槽位生成：

```text
PlcRecipeNameOption
- StationNo：所属工位
- RecipeCode：由槽位顺序得到的隐藏数字配方号
- Name：PLC 读取的用户可见名称
- Address：名称来源地址
```

空名称仍跳过，但不会压缩后续槽位的数字配方号。地址维护页继续显示配方号、名称和地址，供配置人员确认映射。

### 程序持久化

不新增实体和表，继续复用：

```text
BizProgram.RecipeCode         = 工位 1 隐藏配方号
BizProgram.Station2RecipeCode = 工位 2 隐藏配方号
```

`BizProgramRevision` 和 `SaveProgramReq` 继续保存这两个本地字段。`ProgramMesPayloadRules` 继续排除配方字段，MES 载荷不发生变化。

配方名称不持久化。程序保存的是用户当时选中选项的数字配方号。PLC 后续调整槽位名称或顺序时，系统不通过名称自动迁移；现场需要进入程序管理重新选择并保存。

## 程序管理界面

### 程序列表

`dgvPrograms` 删除 `BizProgram.RecipeCode` 列及其本地化表头设置，不增加“程序名称”或其他替代列。筛选和排序不再以配方号作为用户可见主维度；产品工号、程序名称、备注和同步状态仍可用于搜索。

### 工位配方名称选择器

保留现有两个选择器并明确命名为：

- 工位 1 配方名称；
- 工位 2 配方名称。

每个选择器只绑定对应工位的 `PlcRecipeNameOption`。显示文本只使用名称；内部通过选中索引或绑定对象取得 `RecipeCode`。不通过显示文本反向解析数字，不允许手工输入数字配方号。

单工位模式：

- 只显示工位 1；
- 工位 1 必须选择有效名称；
- 不提供“不适用”。

双工位模式：

- 两个工位分别选择，互不自动推断；
- 两个列表均增加“不适用”选项；
- “不适用”对应该工位隐藏配方号为空；
- 至少一个工位必须选择有效名称；
- 两个工位都为“不适用”时禁止保存。

### 名称读取失败

新增程序时：

- 单工位名称读取失败时禁止保存；
- 双工位任一工位名称列表读取失败时禁止保存；
- 选择器不可手工输入数字；
- 提示用户检查 PLC 连接或地址维护中的配方名称配置。

已有程序时：

- 读取失败的工位选择器禁用；
- 用户可以修改备注、程序内容等非配方字段；
- 未修改配方时，保存请求原样保留数据库中的隐藏配方号；
- 读取恢复后才允许重新选择配方。

本次不区分部分槽位失败；读取结果失败即按该工位整体不可编辑处理。

### 历史关联不可用

名称列表读取成功，但已有程序保存的数字配方号不在当前有效选项中时：

- 选择器显示“原关联配方已不可用”；
- 不向用户展示历史数字配方号；
- 未主动更换配方时，保存其他字段仍保留原隐藏值；
- 用户选择当前有效名称后，更新为新选项携带的数字配方号；
- 关联失效期间，该程序不允许在对应工位生产使用。

由于配方名称不持久化，系统不能识别“同一槽位编号但名称业务含义已变化”。只要槽位仍存在且有名称，该数字关联仍被视为有效；现场改变 PLC 槽位内容后需人工重新选择程序关联。

## 保存与校验规则

`ProgramSaveRecipeRules` 从“每个启用工位必须有正整数配方号”调整为以下语义：

- 单工位：工位 1 必须是有效正整数；
- 双工位：工位 1、工位 2 至少一个是有效正整数；
- 任一非空值必须是正整数；
- 空值表示该工位“不适用”；
- UI 新增流程只能从成功读取的选项获得数字值，不接受用户文本输入。

已有程序在名称读取失败或原关联不可用时，UI 将未修改工位的原值带回保存请求，避免非配方编辑清空历史关联。服务层仍规范化并验证实际请求，防止绕过 UI 写入非法数字。

## 按工位解析与下发

### 映射规则

`ProgramRecipeMappingRules.Resolve` 调整为严格按工位读取：

```text
工位 1 → RecipeCode
工位 2 → Station2RecipeCode
```

取消 `Station2RecipeCode` 为空时回退到 `RecipeCode` 的旧兼容规则。空值就是该工位未配置或不适用。

`ResolveTargets` 继续按目标工位生成下发目标，但每个目标只携带本站隐藏配方号。调用方遇到空值时不得借用任务字段、MES 字段或另一工位配方号创建新任务或执行新下发。

### 设备模式

单工位：

- 程序必须配置工位 1；
- 只向工位 1 下发 `RecipeCode`。

双工位双工单：

- 当前工位有隐藏配方关联时程序才可选；
- 工位 1、工位 2 分别使用自己的字段；
- 一侧“不适用”不影响另一侧独立使用。

双工位同工单：

- 同一程序必须同时配置工位 1 和工位 2；
- 一次共享任务需要向两个目标工位分别下发各自配方号；
- 任一工位缺少关联时阻止开工或下发，不进行部分下发。

### 生产程序过滤

程序可用性统一按当前目标工位判断：

- 当前工位隐藏配方号为空或已失效时，从该工位可选程序列表中移除；
- 双工位同工单模式进一步要求两个工位均有效；
- MES 下载但尚未配置本地配方的程序可以保存在程序库中，但不会进入生产可选列表；
- 服务层再次校验配方号，防止绕过界面下发空值。

## 运行中任务兼容

新版本创建的新任务必须从本地程序取得目标工位的有效隐藏配方号。找不到本地程序或本站关联为空时禁止开工，不再回退到：

- MES 程序中的 `RecipeCode`；
- 另一个工位的配方号；
- UI 手工值；
- 新任务中偶然存在的旧配方字段。

为避免升级中断现场，应用启动时从数据库恢复的、已经处于 `Running` 且未完工的任务保留最小兼容：

- 优先使用本地程序当前工位的有效关联；
- 本地关联不可用时，仅回退到该任务自身已保存的 `task.RecipeCode`；
- 回退只适用于任务所属工位，不扩散到共享任务的另一个工位；
- 任务完工后不再保留该兼容路径。

实现时应在恢复任务的边界记录明确状态，而不是把 `task.RecipeCode` 的通用回退继续留在所有新开工和调和路径中。

## 生产监控界面

普通业务页面不展示配方号：

- 移除或隐藏在线、离线开工中的配方号选择控件及其用户编辑事件；
- 用户选择程序后，内部按当前工位解析隐藏配方号；
- 离线程序名称重名时，显示程序名称和产品工号等业务身份，不附加配方号；
- 在线 MES 程序必须能关联本地程序并取得当前工位配方，否则不进入可用列表；
- 工位切换后重新按当前工位过滤和解析程序。

`OfflineStartInputRules.BuildProgramNameOptions` 按传入工位过滤有效程序；显示文本不再包含配方号。`BuildRequest` 仍需要向服务请求写入实际数字配方号，但该值由选中程序内部解析，不来自可见控件。

`MonitorView` 不再维护配方号下拉列表、按配方号反向选择程序或允许用户修改配方号。配方号仍可出现在生产流程日志、异常日志和诊断详情中。

## MES 交互

本次不修改 MES 交互：

- `ProgramDataWriteReq` 不增加配方字段；
- 程序创建和更新继续通过 `ProgramMesPayloadRules` 排除本地配方信息；
- MES 程序下载不推断本地配方号；
- MES 同步状态、备注和待同步动作保持现有规则；
- MES 下载的新程序在本地配方关联完成前不可用于生产。

在线开工可以继续使用 MES 程序列表展示业务程序，但实际 PLC 配方必须来自对应的本地程序记录。不能再以 `ProgramDataRes.RecipeCode` 作为新任务下发的后备来源。

## 简化异常处理

- 配方名称读取失败：禁止新增；已有程序只允许非配方编辑并保留原值。
- 当前工位未配置配方：程序不显示；服务调用时返回明确错误，不下发 PLC。
- 双工位同工单缺少任一侧关联：整体阻止，不做部分写入。
- 原关联不在当前选项：标记不可用，允许非配方编辑，禁止对应工位生产。
- 重复配方名称：本次不校验，用户选择哪个选项就保存哪个选项内部的配方号。
- PLC 槽位名称或顺序变化：不自动迁移，由现场重新选择并保存。

## 主要组件职责

### `PlcRecipeNameReaderService` / `PlcRecipeNameRules`

继续负责从地址维护配置读取各工位名称并生成“工位 + 隐藏配方号 + 名称”的选项。本次原则上不改变其地址计算和槽位映射规则。

### `ProgramManageView`

负责名称选择器绑定、“不适用”状态、读取失败/历史失效状态、保存时提取隐藏配方号，以及移除程序表格配方号列。静态布局和控件属性在 Designer，运行时绑定与校验在代码后置。

### `ProgramManageService`

继续保存两个本地配方字段并写版本快照；调整保存校验语义，不改变 MES 同步载荷。

### `ProgramRecipeMappingRules`

作为所有运行路径的唯一按工位解析入口，取消工位 2 回退，提供“指定工位是否已配置”的可复用判断。

### `MonitorView` / `OfflineStartInputRules`

负责隐藏配方号 UI、按当前工位过滤程序、从程序内部生成开工请求，不再提供配方号手工选择和反向联动。

### `WeldTaskService` / `RecipeCodeReconcileMonitorService`

负责服务层最终保护：新任务和新下发必须取得当前工位有效关联；只对升级前恢复的运行任务保留本站任务快照回退。

## 数据与兼容性

- 不执行数据库迁移。
- 现有 `RecipeCode` 保持工位 1 含义。
- 现有 `Station2RecipeCode` 为空的数据升级后视为工位 2 未配置，不再复用工位 1。
- 历史程序仍可在工位 1 使用有效 `RecipeCode`。
- 历史程序若要用于工位 2，需要在程序管理重新选择并保存。
- MES 下载程序未配置本地映射时保留在程序库，但不可生产。
- 版本快照继续记录两个隐藏字段，便于审计和恢复。

## 用户提示与本地化

需要补充或调整多语言文本：

- 工位 1/2 配方名称；
- 不适用；
- PLC 配方名称读取失败，请检查 PLC 连接或地址配置；
- 原关联配方已不可用；
- 当前工位未配置 PLC 配方；
- 双工位同工单必须配置两个工位配方；
- 至少选择一个适用工位；
- MES 下载程序尚未配置本机 PLC 配方。

错误提示面向用户使用配方名称和工位描述，不主动暴露数字配方号。诊断日志可以记录数字值。

## README 更新

本次改变程序维护和生产操作方式，必须同步更新 `README.md`，说明：

- 程序管理通过各工位 PLC 配方名称选择建立隐藏配方号关联；
- 双工位左右配方号相互独立；
- 配方号只在地址维护映射和诊断信息中可见；
- 未配置当前工位配方的程序不能用于生产；
- MES 下载程序需要完成本机配方关联后才能开工；
- PLC 槽位调整后需要重新选择并保存程序关联。
