# 数据管理界面通用化与测试历史树形化设计

日期：2026-08-18

## 目标

数据管理页不再依赖“焊接参数”固定概念，统一显示点焊系统与检测设备的测试数据；测试记录按产品展开为树形表格；移除与测试树重复的采集数据页签，并把原始 JSON 合并到测试树下方的可拖动分隔面板。

## 设计

- 历史工单和下方详情继续使用水平 `AntdUI.Splitter`，默认约按 25%/75% 分配高度，只在页面加载时初始化，不持久化用户拖动位置。
- 详情页只保留“测试数据”和“报告文件”。
- 测试数据页内部使用水平 `AntdUI.Splitter`：上方为产品→测试记录树，下方为紧凑的原始 JSON 面板，用户可拖动分隔线展开。
- `DataHistoryTestDataRow` 子行携带 `RawDataJson`；选中子行显示对应 JSON，选中产品父行时清空原始数据。
- `DataManageView` 只调用 `QueryTestDataAsync` 和报告查询，不再调用重复的采集分页查询；公共采集查询接口暂时保留兼容。
- 动态测试列只依据 `SaveEnabled` 生成；原始 JSON 仍可保存报表/MES需要的其他字段。
- 产品父行按工位和产品号聚合，产品结果沿用记录中的 PLC `ProductResult`，不由子记录结果推断。

## 验收

- 下方测试数据区域默认明显大于历史工单区域，两个区域均可通过 splitter 调整。
- 详情页不再显示“采集数据”页签。
- 产品节点默认展开，选中测试记录后下方显示格式化原始 JSON。
- 控制台回归测试、隔离输出目录解决方案构建和 `git diff --check` 通过。
- 未执行真实 PLC、MES、中心服务器、MySQL 或人工 UI/DPI 验证。

## 边界

- 不新增数据库字段，不迁移历史记录。
- 数据管理页上的两个分隔控件统一使用 `AntdUI.Splitter`，不保存 splitter 布局状态。
- 当前工作区已有的 PLC、中心服务、版本等未提交修改不纳入本次功能范围。
