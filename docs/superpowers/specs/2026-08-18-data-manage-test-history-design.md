# 数据管理界面通用化与测试历史树形化设计

日期：2026-08-18；修订：2026-08-20

## 目标

数据管理页不再依赖“焊接参数”固定概念，统一显示点焊系统与检测设备的测试数据；测试记录按产品展开为树形表格；移除与测试树重复的采集数据页签，并隐藏普通用户无需关注的原始 JSON。

## 设计

- 历史工单和下方详情继续使用水平 `AntdUI.Splitter`，默认约按 25%/75% 分配高度，只在页面加载时初始化，不持久化用户拖动位置。
- 详情页只保留“测试数据”和“报告文件”。
- 测试数据页由产品→测试记录树直接填满，不再提供原始 JSON 面板或内部 splitter。
- 数据历史与中心转发统一按任务绑定程序和记录工位解析产品工艺，避免工单产品号与程序产品号不一致时丢失动态测试项。
- `DataHistoryTestDataRow` 继续携带 `RawDataJson`；方案明细中启用“保存历史”的角色用于本地动态列和中心看板，报表或 MES 独占角色不会进入这两条路径。
- `DataManageView` 只调用 `QueryTestDataAsync` 和报告查询，不再调用重复的采集分页查询；公共采集查询接口暂时保留兼容。
- 动态测试列只依据 `SaveEnabled` 生成；原始 JSON 仍可保存报表/MES需要的其他字段。
- 产品父行按工位和产品号聚合，产品结果沿用记录中的 PLC `ProductResult`，不由子记录结果推断。

## 验收

- 下方测试数据区域默认明显大于历史工单区域，两个区域均可通过 splitter 调整。
- 详情页不再显示“采集数据”页签。
- 产品节点默认展开，测试记录子行显示本工位方案中启用“保存历史”的动态值；测试数据页不显示原始 JSON、原始数据文本框或内部分隔线。
- 工单产品号与程序绑定产品号不同时，本地历史和中心转发仍使用与产品采集相同的工艺方案。
- 控制台回归测试、隔离输出目录解决方案构建和 `git diff --check` 通过。
- 未执行真实 PLC、MES、中心服务器、MySQL 或人工 UI/DPI 验证。

## 边界

- 不新增数据库字段，不迁移历史记录。
- 数据管理页只保留工单与详情区域之间的 `AntdUI.Splitter`，不保存 splitter 布局状态。
- 当前工作区已有的 PLC、中心服务、版本等未提交修改不纳入本次功能范围。
