# 程序管理删除卡死修复设计

## 目标

修复程序管理页单条删除和批量清理在部分工控机上导致 WinForms 界面完全无响应的问题。保留程序历史版本功能，不删除或迁移 `Biz_ProgramRevision` 历史数据。

## 根因

当前删除入口在 UI 线程调用同步数据库操作。`DeleteAsync` 在真正遇到 MES `await` 前，会同步完成数据库查询、程序状态更新、历史版本写入和操作日志写入；勾选立即同步后还会等待 MES 删除请求。`BatchDeleteLocalProgramsAsync` 虽返回 `Task<int>`，内部却同步查询、物理删除和写操作日志。故障机上的 MySQL 锁等待、数据库 I/O、数据积压或 MES 网络异常会阻塞 UI 消息循环。

## 单条删除设计

- 删除按钮执行期间禁用，避免重复点击。
- 先完成本地删除状态更新：标记 `IsDeleted`、递增版本、更新同步状态，并保留现有 `Biz_ProgramRevision` 快照和操作日志行为。
- 本地删除完成后立即刷新程序列表并恢复界面。
- 如果选中“保存后立即同步”，MES 删除改为后台执行，不再由 UI 等待网络调用。
- 后台同步完成后通过 UI 线程安全刷新对应程序状态；失败由现有同步流程记录为 `Failed`，用户可在后续同步流程中重试。
- 保留 MES 超时和取消令牌，不改变远程删除接口语义。

## 批量清理设计

- 保留当前清理目标：当前程序列表中所有 `SyncStatus != Synced` 的程序。
- 保留现有物理删除语义，不改为软删除，不清理或删除历史版本表。
- 数据库查询、删除和操作日志写入改为真正的可等待后台流程，不在 UI 线程直接执行。
- 保留空目标快速返回和去重行为。
- 增加 `CancellationToken` 贯穿批量操作；UI 关闭或用户取消时停止后续处理。
- 对批量目标按受控批次处理，避免一次性加载过多程序实体造成长时间数据库操作。
- 删除失败时事务回滚当前批次，并向 UI 返回明确错误；按钮状态始终在 `finally` 中恢复。

## 数据库与错误保护

- 不修改 `Biz_ProgramRevision` 表结构和已有历史记录。
- 使用现有数据库锁/事务模式，保证单次批量删除的数据库状态一致。
- 对数据库操作增加明确超时或使用项目现有数据库超时配置；不允许异常无限期占用 UI 线程。
- 保留操作日志，日志失败时按现有错误处理策略反馈，不隐藏数据库删除异常。

## UI 状态

- 单条删除和批量清理执行期间禁用对应按钮。
- 单条本地删除完成后立即恢复界面；后台 MES 同步不阻塞窗口。
- 批量清理期间显示处理中状态，完成后刷新列表并提示数量。
- 异常、取消和无目标场景均恢复按钮状态。

## 验证

- 增加服务/UI 回归检查，覆盖：单条删除先完成本地状态、立即同步走后台、批量空目标、批量成功、批量异常和取消路径。
- 运行控制台回归 harness。
- 使用 `E:/Desktop/AutoWeldSystem/artifacts/verify-bin/` 备用目录构建解决方案。
- 不以本地构建替代现场 MySQL、MES、PLC 或真实 UI 自动化验证；这些依赖需单独报告。

## 不包含

- 不移除程序历史版本功能。
- 不删除或迁移现有 `Biz_ProgramRevision` 历史数据。
- 不改变 MES API、同步状态定义或批量清理的业务目标范围。
