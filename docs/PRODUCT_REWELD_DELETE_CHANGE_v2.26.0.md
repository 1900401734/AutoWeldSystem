# 产品重焊/删除与程序计数模式变更说明（v2.26.0）

| 项目 | 内容 |
| --- | --- |
| 软件版本 | v2.26.0（上一版 v2.25.0） |
| 变更范围 | 生产监控页产品历史右键操作；系统设置新增「产量统计来源」；完工上报数量口径；上传模式切换说明；数据管理页「采集数据」页签权限 |
| 影响对象 | 操作员（监控页操作）、班组长/管理员（系统设置与权限）、MES 完工数量、中心看板计数与报表 |
| 需客户确认 | 是否启用「程序统计」模式；报表产品编号允许断号；完工数量改由软件统计后与 PLC 计数器的差异可接受 |
| 待现场验证 | 见文末「待现场确认事项」 |

## 一、变更背景

现场提出两个需求：

1. **重焊/重测**：某件产品焊坏或检测不合格，希望重新焊一遍（整件检测设备是重新检测一遍），让新数据**覆盖**这件产品原来的记录，而不是多出一件新产品。
2. **删除**：某件产品是误触发采集或不该计入的，希望把它**删掉**，不上传 MES、不进报表、不算产量。

这两个操作都会改变本地的产品数量，而完工上报给 MES 的「实际数量/合格数量/失效数量」此前一直是**从 PLC 计数器读取**的——PLC 只知道它焊了多少件，不知道软件里删了哪件。为了让上报数字与软件里看到的一致，本次同时增加了一个开关：**产量由软件按实际采集记录统计，不再依赖 PLC 计数器**。产品编号也随之改由软件自动编号。

升级后**默认仍是原来的 PLC 计数方式，行为不变**；重焊/删除功能只在切换到「程序统计」后才出现。

## 二、系统设置：产量统计来源

位置：**系统设置 → 生产配置 → 产量统计来源**，两个选项：

| 选项 | 含义 |
| --- | --- |
| **PLC 计数**（默认） | 与升级前完全一致：产品编号从 PLC 读取，完工数量从 PLC 计数器读取。监控页产品历史右键只有「标记为试焊件」。 |
| **程序统计** | 下面三件事同时生效，不能单独选择：① 产品编号由软件自动生成；② 完工上报的三项数量由软件统计；③ 监控页产量指标按同一口径显示。同时开放产品历史右键的「重焊/重测」「删除」「撤销删除」。 |

**切换限制**：存在未完工的任务时不允许切换，保存会提示先完工。原因是同一张工单前半段按 PLC、后半段按软件统计，完工数字会说不清楚。

### 2.1 程序统计模式下的产品编号

- 每张工单、每个工位各自从 **1** 开始递增：1、2、3……，与现场 PLC 现在给出的编号形状一致，报表上看不出区别。
- **已删除产品的编号不会被重新使用。** 例如删掉 5 号，下一件仍是 6 号。因此报表明细的产品编号可能出现断号（1、2、3、4、6……），**这是预期行为**，断号处即为被删除的产品。
- 产品工艺里的「产品编号偏移」在该模式下改为可选。若仍配置了它，软件会继续读取 PLC 编号，但只用来识别整件检测触摸屏的「重测」动作（见 3.3），不作为产品编号。

### 2.2 程序统计模式下的完工数量

上报 MES 完工时的三项数量按软件采集记录计算：

| 字段 | 口径 |
| --- | --- |
| 实际数量 | 该工单下两个工位已完成采集且**未被删除**的产品数（按产品编号去重，一件多焊点只算一件） |
| 合格数量 | 上述产品中产品结果为 **OK** 的数量 |
| 失效数量 | 实际数量 − 合格数量（产品结果未知的产品归入失效，保证三项恒等） |

补充说明：

- **试焊件照常计入**这三项数量。报表和过程参数里都有试焊件标志，客户可据此自行区分。
- 监控页的实际数量、合格数量、失效数量和良率改为按同一口径显示，操作员在屏幕上看到的数字就是完工上报的数字。
- 该模式下 PLC 计数器读取失败**不再阻止完工**；「完工上报实际数量输入弹窗」设置在该模式下不起作用。
- 每次完工会在「日志管理 → 程序异常日志」写一条 `PLC.FinishQuantity.Compare` 业务记录，同时列出软件统计值与 PLC 计数器读数，供现场对账排查。

## 三、产品历史右键：重焊 / 重测

位置：生产监控页 → 产品历史表格 → 在产品行或其任一焊点行上**右键**。整件检测设备菜单文字显示为「重测」，点焊设备显示为「重焊」，含义相同。

### 3.1 操作步骤

1. 右键要重焊的产品，点「重焊」。该产品状态列变为「**待重焊**」。
2. 操作员在设备上重新焊接这一件。PLC 触发采集时，新数据**覆盖**这件产品：产品编号不变，测试值、结果、采集时间更新为新一轮。
3. 覆盖完成后「待重焊」标记自动清除，之后的产品恢复正常追加。

### 3.2 规则

- **同一工位同时只能预约一件。** 若又对另一件点「重焊」，预约会转移到新选的产品。
- 预约后、PLC 尚未触发前，可右键「**取消重焊**」撤回。
- 覆盖后该产品的上传状态重置为「待上传」，会按当前上传模式重新上报 MES（数量模式下不等凑批，单独立即重传）。
- 覆盖**不会**清掉已标记的试焊件；产品编号、在表格中的顺序也不变。

### 3.3 与整件检测触摸屏「重测」的关系

- **PLC 计数模式**（默认）：整件检测设备保持原有行为——触摸屏点「重测」后 PLC 发同一个产品编号，软件识别为重测并覆盖。点焊设备无重测功能，与升级前一致。
- **程序统计模式**：整件检测设备一般不建议切换到该模式。若切换，触摸屏「重测」仍可被识别（软件比对 PLC 发来的编号是否与上一件相同），但**软件里的「重测」预约优先**——两者同时存在时按预约的产品覆盖。

## 四、产品历史右键：删除 / 撤销删除

### 4.1 删除

1. 右键产品，点「删除」，弹出确认框，确认后生效。
2. 该产品行**仍留在表格里**，产品名前加「[已删除]」，状态列显示「已删除」。
3. 删除后的效果：
   - 不再上传 MES；若它已经排在待上传队列里但尚未传成功，该上传任务标为「已跳过」，不会再重试。
   - 不进入上传报表、数据管理页「测试数据」、中心看板可见报表与当日计数。
   - 不计入程序统计模式的产量三项。
   - 它占用的产品编号不会被后续产品复用。
4. 删除会写入操作日志，记录操作员工号与产品编号，便于事后追溯。

### 4.2 撤销删除

右键已删除的产品，点「**撤销删除**」即恢复：重新计入产量与报表，上传状态回到「待上传」并按当前上传模式重新排队。

## 五、哪些产品可以操作（重焊/删除/试焊件共用规则）

只有**尚未上传 MES** 的产品可以重焊、删除或改试焊件标记。产品下任一焊点已上传、上传中或已跳过，右键菜单对应项置灰并显示原因。已上传到 MES 的数据无法从 MES 侧撤回，因此软件不提供看起来能改、实际改不了的按钮。

可操作的范围取决于「系统设置 → 上传模式」：

| 上传模式 | 何时上传 | 可重焊/删除的产品 |
| --- | --- | --- |
| 实时（Realtime） | 每件采集完立即上传 | 几乎只有刚采完、尚未传成功的那一件 |
| 数量（Quantity） | 凑满批次后，等**下一件**采完再传上一批 | 通常是最近一两件 |
| 批量（Batch） | 全部推迟到完工时一次性上传 | 整张工单期间的所有产品 |

若现场希望「任意产品都能重焊/删除」，请将上传模式设为**批量**。

## 六、上传模式切换即刻生效

「上传模式」保存后**立即生效，不需要重启软件**：下一件产品采集完成时就按新模式处理。切换时需要知道：

- 切换只影响**之后**采集的产品。工单内已经积压的「待上传」产品不会因切换被主动补传，仍在完工时统一补传（从批量切到实时/数量时尤其要注意）。
- 数量模式的批次在排队时已固定，改「上传批次大小」不影响已排队的批次。
- 重焊/删除的可操作范围随之变化（见第五节）。
- 系统设置页的所有配置都是保存即生效；PLC 地址、端口、心跳等保存后软件会自动重连 PLC。唯一需要重启软件才生效的是配置文件里的数据库连接串，该项不在设置页内。

## 七、中心看板

- 删除或撤销删除会自动同步到中心看板：被删除的产品从看板当日计数和可见报表中移除，撤销后恢复。
- **限制**：看板当日计数只统计当天完成的产品。若某件产品在**第二天**才被删除，看板历史日计数不会回退（设备端完工上报给 MES 的数字是正确的，只有看板的历史日统计可能偏大）。

## 八、数据管理页

- 「测试数据」页与报表口径一致，**不显示**已删除产品。
- 「采集数据」页签（显示原始焊点行，含已删除产品和新增的「已删除」列）改为**按权限显示**：默认仅开发者账号可见；管理员如需查看，可在「用户管理 → 角色权限」中授予「采集数据页签」权限。

## 九、缺陷修复

整件检测设备触摸屏「重测」覆盖产品数据时，会把操作员已标记的「试焊件」静默清成未标记。此前因整件检测不显示试焊件列而无可见症状，本次已修复：重测/重焊覆盖后试焊件标记保留。

## 十、升级注意

1. 数据库焊点记录表会**自动**新增两个字段（已删除、待重焊）和一个**唯一索引**（工单 + 工位 + 产品编号 + 焊点编号）。旧库若存在重复记录，建索引会失败并导致软件启动报错。**升级前请在现场数据库执行以下查询确认结果为空**：

```sql
SELECT TaskId, StationNo, ProductNo, TouchNo, COUNT(*) AS Cnt
FROM Biz_WeldPointRecord
GROUP BY TaskId, StationNo, ProductNo, TouchNo
HAVING COUNT(*) > 1;
```

   若有结果，需先清理重复行（通常保留 Id 最大的一条）再升级。

2. 「产量统计来源」升级后默认为「PLC 计数」，不切换则一切行为与 v2.25.0 相同。
3. 中心服务器需同步升级到 v2.26.0，否则设备端删除产品的信息看板无法识别（旧版看板会把删除当作普通数据更新）。
