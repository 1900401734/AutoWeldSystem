# AutoWeldSystem

自动点焊系统上位机软件，用于对接 PLC、MES 和本地程序管理流程。当前版本：`v2.14.0`。

## v2.14.0 更新说明

- 「特定数量」上传模式改为**滞后一个产品**：凑满批量值后不再立即上传，要等下一个产品采集完成时才提交上一批，避开产品刚采完那一刻。例如批量值为 3 时，采完第 4 件才上传前 3 件；批量值为 1 时，采完第 2 件才上传第 1 件。
- 凑满批量值却等不到下一个产品就完工的情况，由完工时的过程参数补传兜底，数据不会丢。
- 重测重传不受影响，仍绕过批次立即上传——重测属修正性操作，数据正确性优先。
- 双工位各自独立计数，一个工位的产品不会凑另一个工位的批次。「实时上传」和「批量上传」两种模式行为不变。

## v2.13.0 更新说明

- 系统设置的 PLC 一组新增“报表小数位”和“过程参数小数位”，可分别指定 XLSX 报表和 MES 过程参数输出的小数位。**留空表示沿用采集时的小数位**，因此升级后不配置就与之前完全一致。取值范围 0-10，0 表示输出整数。
- 截断还是四舍五入沿用系统设置里已有的“PLC 数值格式处理方式”，不另设模式；关闭“启用 PLC 数值格式处理”时按四舍五入，与采集侧口径一致。两个小数位互相独立，报表配几位不影响过程参数。
- 只作用于测试项数值列。工位、产品编号、面号、面结果、产品结果等固定列，以及 `OK`/`NG` 结果文本和整件检测 B 行宽度的 `\` 标记都不会被改写。过程参数是先按小数位格式化再追加单位。
- **两条使用限制**：① 采集时已按偏移量表达式的小数位格式化后存库，输出端只能减位或补零——采集配 `_2` 存下 `15.88`，报表配 3 位得到的是 `15.880` 而不是 `15.883`，恢复不了被截掉的精度；② 存在二次舍入，采集舍一次、输出再舍一次，与直接从原始值一次舍入可能差一个末位。需要更高精度请改测试项偏移量表达式里的小数位。
- 界面显示不受影响：实时预览和历史数据仍按采集小数位显示，因此界面与报表、过程参数的位数可能不同。

## v2.12.0 更新说明

- 整件检测“程序计算”模式下修复零值误判：视觉检测失败时约定回传 `0`，而判定只比较上限，`0` 必然小于上限，于是“没测到”被判成 OK。现在 A/B 合并后的 `高度`、`宽度` 仍为 `0`（或负值）时判 NG，并在合并视图标红对应列。判定只发生在合并值这一层，单面检测失败仍由其他面的有效值兜住，不会把该面结果或 A/B 行结果污染成 NG。`对称度` 真值可能为 0，不做零值检查。
- `宽度` 改为只取 A 面：现场产品 A、B 两面宽度不同，且过程参数与报表只要求上传 A 面宽度。A 行取面2、面4 的最大值，B 行留空——MES 过程参数 B 行的宽度字段传空字符串（靠 `SideNo` 区分 A/B 行），XLSX 报表 B 行显示 `\`，并且宽度列不再按产品跨行合并单元格。`高度` 仍取四面最大值、A/B 两行同值、可跨行合并。生产监控合并视图不变，`高度`、`宽度` 仍各占一列，宽度显示 A 面值。
- `宽度` 的上限只对 A 面有意义，因此 B 面（面1、面3）的宽度**不参与面级程序判定**。此前面级判定拿每一面自己的宽度去比那个按 A 面设定的上限，B 面宽度不同、超限就把该面判成 NG，进而让 MES 过程参数和 XLSX 报表里 B 行的 `Result` 变成 NG——即使产品结果按 A/B 合并值判定仍是 OK。现在 B 面只用高度、对称度等其余测试项判定。该过滤只在四面整件检测工艺下生效。
- “A/B配对聚合方式”默认值由 `配对平均值` 改为 `配对最大值`。取平均会把检测失败回传的 `0` 拉进结果，反而更容易判 OK；取最大值时单面失败会被有效面自然覆盖。**已部署的现场数据库保留原有设置，需要在系统设置页手动改一次**。
- 新增“整件检测逐面结果显示”开关：逐面模式下可隐藏“面结果”列，面号和逐面实测值全部保留，避免单面结果与合并后的产品结果口径不同造成歧义。可在生产监控页实时切换（实时预览表格上方“面结果”复选框，仅整件检测且未开启合并显示时出现），系统设置页有同名开关且始终同步。该开关只影响界面，面结果照常计算、入库并进入历史数据和报表。
- 口径变化提示：XLSX 报表在导出时实时聚合，不是导出后固化。上述改动生效后重新导出**以前的产品**，宽度会从“四面最大值”变成“A 面最大值”、B 行变成 `\`，对称度按新的默认聚合方式计算，与此前已交付的报表不一致。中心端报表为逐面明细口径，宽度不再按产品级最大值覆盖，改为显示四面各自的原始值。

## v2.11.0 更新说明

- “实时编号来源”选为“程序判断”时，实时预览不再从 PLC 读取实际数量与预设数量：已完成数量按检测结果连续推算（面结果为 OK 或 NG 才算完成，中途未完成即停止计数，PLC 残留结果不会让计数跳号），预设数量取产品工艺配置的数量。实时预览表格同步改为逐面出现，只显示已完成的面，不再一次铺满全部行。选为“PLC读取”时行为与之前完全一致。
- 系统设置两处文案改为通用表述，兼顾检测设备与点焊设备：“实时焊点编号来源”改为“实时编号来源”，“启用 PLC 字符串数值处理”改为“启用 PLC 数值格式处理”（后者自 v2.10.1 起已同时作用于数值类型，原文案已不准确）。

## v2.10.1 修复说明

- 数值类型（Int16/Int32/Float）的 PLC 读值此前只按偏移量表达式的小数位格式化，固定四舍五入，忽略系统设置里的“PLC字符串数值处理方式”；只有 String 类型才遵守该设置。结果是把处理方式选为“截断”时，实时预览和新采集的产品历史仍按四舍五入显示，与 MES 上传、XLSX 报表的数值对不上。现改为两者共同作用：小数位仍由偏移量表达式决定且始终生效，截断还是四舍五入由系统设置决定，界面与上传、报表口径统一。
- “启用PLC字符串数值处理”关闭时数值类型按四舍五入处理，与本次修复前的行为一致；已入库的历史数据保持原样，本次修复只影响此后新采集的数据。

## v2.10.0 更新说明

- 整件检测（四面）新增“整件检测四面合并显示”开关，开启后生产监控的实时预览和产品历史把四面数据合并成一行显示，列为 `高度`（四面最大值）、`宽度`（四面最大值）和按 A/B 配对的 `对称度A`（面2、面4）、`对称度B`（面1、面3），使界面显示与 MES 过程参数、XLSX 报表口径一致。四面明细照常入库，可关闭开关回到逐面显示。开关只影响界面，不改变上传和报表行为。
- 合并显示可在生产监控页实时切换：实时预览表格上方（“实时采集正常 产品编号：…”那一行右侧）有“合并显示”复选框，勾选或取消后两个表格立即重建，无需重启程序，也不必进系统设置页。切换结果会记住，下次启动保持上次视图；系统设置页的同名开关与监控页复选框始终同步。该复选框仅在过程参数设备类型为整件检测时显示。
- 合并显示下产品判 NG 时，实时预览会把超出程序设定值的那一列标成红底白字（例如只有 `对称度B` 超限就只标该列，`高度` 保持原色），不必取消合并逐面排查。该提示依据程序判定结果，只在“检测结果来源”为“程序计算”时出现；“PLC读取”模式下 PLC 只返回结果不返回依据，不做标红。产品历史表暂不标红，需要定位到面时取消合并查看四面明细。
- 新增“A/B配对聚合方式”设置：`配对平均值`（默认，与旧版本一致）或 `配对最大值`。高度和宽度始终取四面最大值，不受该设置影响。该设置会改变上传和报表数据，存在未完工任务时禁止切换。
- 整件检测选择“程序计算”时，产品 OK/NG 改为按 A/B 合并值与程序设定值比较判定（A、B 两行分别判定后取并），与上传和报表使用同一组数据；各面结果仍按面判定并保留在明细中。
- 新增 PLC 地址逻辑键 `product_result_feedback`（产品结果反馈）：四面采集入库后回写产品判定结果，`3=OK`、`2=NG`。地址未配置或 PLC 未连接时跳过回写，不影响采集握手；该回写不是握手信号，写失败只记录日志不重试。

## 功能概览

- 生产监控：工单信息、程序信息、PLC/MES 连接状态、设备状态、生产指标实时显示；采集预览和产品历史仅在开工后显示，无运行任务且无待开工工单或离线草稿时清空工单信息；右侧区域按可用高度与 DPI 自动切换紧凑布局，仅在极低高度下纵向滚动。 产品工艺仅配置一个采集点且产品只有一条记录时，产品历史直接显示为单行；多采集点或重复测试仍保留树形明细。
- 产品重测：仅整件检测设备支持。PLC 触摸屏点击“重测”后不更新产品编号，上位机识别为重测并就地覆盖该产品的测试值、结果和采集时间，产品历史、报表、MES 过程参数和中心看板均更新为最新一轮结果，重测记录写入操作日志。
- MES 交互：员工校验、工单获取、开工上报、完工上报、设备编号同步、程序上传/下载。
- 过程参数上传：测试项字典配置单位后，实际值、上限和下限按“值 单位”上传，结果字段保持原值；试焊件字段 `IsTest` 使用 JSON 布尔值 `true/false`；整件检测四面工艺在本地保留 1～4 面原始数据，上传 MES 时输出 `SideNo=A/B` 两条数据，对称度按 A=面2/4、B=面1/3 聚合（聚合方式见“A/B配对聚合方式”设置，默认取最大值），高度取四面最大值并在 A/B 两条数据中重复发送，宽度只取 A 面（面2、面4）最大值、B 条数据的宽度字段传空字符串，`Result` 按配对面从严合并，不发送 `Type`、`TouchNo` 和 `IsTest`。数值字段先按“过程参数小数位”设置格式化再追加单位，该设置留空时沿用采集小数位。
- PLC 监控日志：周期读取设备状态、实际数量、合格数量和失效数量失败时记录为“PLC 业务信号读取失败”；“生产数据采集失败”仅表示开工后的产品数据就绪信号触发实际产品数据采集失败；报警地址读取失败单独记录。PLC 心跳支持独立配置监测频率、心跳超时时间和通讯超时，并在状态提示中显示采样间隔、通讯锁等待和 PLC 读取耗时。
- PLC 报警通知：多条 PLC 报警在屏幕左下角以 Notification 完整展示。报警地址属于整台设备，不区分工位，因此通知标题不带工位号，双工位也只弹一张卡片。通知支持手动关闭，报警恢复后自动关闭；右侧异常摘要点“清除”会同时关闭通知卡片并按当前报警内容标记为已读，报警内容变化或恢复后重新弹出。
- 设备状态上报：JSONL 本地记录与 MES `Remark` 使用同一格式；单工位使用“开机/停机/程序执行开始/程序执行结束”，双工位的程序边界使用系统设置映射生成“左工位：程序执行开始”等文本；报警地址的 PLC 工位不进入备注，异常统一为“异常：报警内容”或“异常恢复：报警内容”。
- 实时预览：每个面/焊点先读取 PLC 拍照结果或焊点结果作为完成门禁，只有 `OK/NG` 才显示该面的测试值；未测试、清零残留、读取失败和焊前 NG 显示 `--`，真实的 `0/0.00` 在有效结果下正常显示，下一次 PLC 清零后不会保留上一帧数据。整件检测选择“程序计算”时，界面显示程序按最大允许值计算的单面结果，任一已完成面 NG 时产品立即显示 NG，四面全 OK 后才显示 OK。
- 程序管理：本地程序版本管理、提交记录、MES 同步状态，以及按工位选择 PLC 配方名称并隐藏保存槽位配方号；保存、校验和同步结果使用非阻塞全局提示，不影响继续操作主界面；删除确认框绑定主窗体显示，始终位于主程序之上。
- 生产监控：产品工号筛选程序与双工单切换入口位于工单信息区，复选框悬停可查看完整说明；单工位时双工单开关自动禁用。`UseProductNumberFilter` 同时影响在线和离线开工的程序列表筛选。
- 系统设置：应用全部优先保存本地配置；仅在设备编号、名称或相关服务地址发生变化时后台同步设备信息到 MES，保存和同步结果使用非阻塞全局提示。整件检测设备可将“检测结果来源”切换为 `PLC读取` 或 `程序计算`，存在未完工任务时禁止切换。整件检测还可开启“整件检测四面合并显示”和“整件检测逐面结果显示”（两者都只影响界面）并选择“A/B配对聚合方式”（影响上传和报表数据，存在未完工任务时禁止切换）。PLC 一组的“报表小数位”和“过程参数小数位”分别控制 XLSX 报表和 MES 过程参数输出的小数位，留空表示沿用采集小数位，截断还是四舍五入沿用同组的“PLC 数值格式处理方式”。
- 中心服务器同步：中心服务器未启动或网络不可达时仍按配置周期探测，连接类失败只在服务器日志记录首次、每 10 分钟持续故障摘要及恢复状态，不写入程序异常日志；服务端已应答的业务失败也只保留在服务器日志。
- 待上传数据：工单信息页签持续显示未完工任务及开工、过程参数、xlsx 报表和完工上报四阶段状态，直到任务完成且相关上传阶段处理完毕；生产期间可增量生成本地 XLSX，设备端和中心服务器报表会在实际值、上限、下限列标题后追加测试项单位，结果列不追加单位；报告文件必须等待 MES 完工上报成功后才允许上传，启动补传和手动重试同样遵守该顺序；切换各上传页签时会刷新绑定字段元数据，避免有记录但单元格空白。
- 数据管理：使用通用“测试数据”页签兼容点焊与检测设备，按产品展开测试记录树；按任务绑定程序和工位解析对应方案，方案明细中勾选“保存历史”的动态测试项会写入本地历史，并在启用中心同步时转发到中心服务器看板，报表或 MES 独占字段不会展示；原始数据仅供内部流程使用，不在界面展示；报告文件入口独立保留。 当产品工艺仅配置一个采集点且该产品只有一条测试记录时，直接显示为单行；多采集点或重复测试仍保留产品到测试记录的树形结构。 支持按产品结果筛选全部/OK/NG 数据，点击动态测试列按产品升降序排列，并将当前筛选和排序后的测试明细导出到用户指定的 XLSX 路径（导出始终覆盖当前筛选的全部产品，不受分页影响）。 测试数据按产品行分页，默认每页 20 个产品，可切换 20/50/100；产品节点默认折叠，工具栏可一键展开或折叠全部测试记录。 历史工单支持多选删除、清理上传失败工单和按筛选日期区间批量清理，删除会级联清除该工单的采集记录、上传任务、报表记录以及磁盘上已生成的 xlsx 报表；生产中和已暂停的工单会被自动跳过，需要“删除历史数据”权限，删除结果写入操作日志。
- 地址维护：维护固定业务信号对应的 PLC 实际地址，并按工位配置/预览 PLC 配方名称与数字槽位的映射；“启用采集”只控制实时预览，“保存历史”同时决定本地历史展示和中心服务器转发字段，“写入报表”和“上传 MES”可独立配置；各维护页签可按角色独立授权。
- 测试项字典的实际值、上限、下限和结果表达式同时支持相对地址与绝对地址：相对地址如 `14:F-0_2` 按测试项基地址和焊点偏移计算，绝对地址如 `DB97.26:F-0_2` 直接读取指定 PLC 地址，不叠加测试项基地址和焊点偏移。
- 日志管理：MES 交互日志表格按发送时间、接口路径、请求原因、方法、HTTP、结果和耗时展示，完整请求地址及请求/响应正文保留在详情中；MES 交互、生产流程、程序异常、设备、设备状态和服务器日志页签可按角色独立授权。
- 权限管理：本地用户、角色、页面、页签和按钮权限控制。启动权限初始化会清理已废弃的“导出数据”权限及其角色关联；旧库首次引入日志/地址页签权限时，会为已有对应页面权限的非开发者角色一次性补齐全部页签，后续保留管理员手工调整结果。
- 国际化：支持简体中文和英文界面切换。

## 程序管理界面操作

- 左侧列表按产品工号去重，首列按当前筛选结果显示分组序号，程序名称和同步状态分列显示，不再展示本地版本号。
- 列表按更新时间倒序排列：工号行按该工号下最新的程序更新时间排序，同工号的子程序也按更新时间倒序，最近改过的程序排在最前。更新时间相同时按工号排序，顺序稳定。
- 列表底部为分页控件，默认每页 20 个产品工号，可切换 20/50/100。设备可存放上百个加工程序，分页后列表不会一次铺满。序号在分页前生成，因此翻页后序号仍然全局连续（第 2 页从 21 开始）。
- 工具栏右侧是查询控件，左侧“刷新”按钮、中间关键字输入框、右侧“搜索”按钮合并在一起。输入关键字后按回车或点“搜索”执行筛选；点“刷新”或清空关键字后再次搜索，会重新载入程序列表和 PLC 配方名称并恢复完整列表。关键字不再逐字符触发筛选。
- 搜索会回到第 1 页。保存、另存为、同步、删除和刷新后列表会自动翻到正在编辑的程序所在页并保持选中；手动翻页只切换可见页，不改变右侧正在编辑的内容。
- 工具栏“保存后立即同步”复选框控制保存和删除后是否马上向 MES 同步，默认勾选，行为与此前一致。
- 右侧当前程序状态仅显示“当前：已同步 / MES程序ID”或“当前：未同步”；本地新建状态继续显示“当前：新建本地程序”。
- 工号下有多个程序时，该行左侧出现展开箭头，展开后每个程序占一个子行，按更新时间倒序排列，子行仍显示各自的流水号标签；子行序号留空，程序名称和同步状态分别显示在独立列中。点击子行切换右侧编辑内容。
- 工号下只有一个程序时不出现展开箭头，程序名称和同步状态直接显示在工号父行对应列中；点击工号行即可编辑，避免为单个程序多套一层。
- 同一工号下可以有多个程序，用“另存为新程序”按当前内容新建一条，流水号自动取该工号下的下一个可用值。
- 在线、离线、配方匹配和程序列表使用轻量程序快照；程序内容与历史执行文件只在选中或开工时按需加载，避免重复读取大字段阻塞界面。
- 产品工号、部件图号和工位配方名称为必填项，标签前带红色星号，留空时保存会立即提示。其余字段可以留空。
- 程序名称由工号、部件图号、流水号和程序备注拼成。部件图号在名称中原样保留用户输入（例如输入 `RY.682.100` 名称里就是 `RY.682.100`），工号仍去掉 `#`，程序备注仍只保留字母、数字和短横线。同工号下若流水号和程序备注都相同会产生重名，保存时会被拒绝，需调整流水号或程序备注。

## PLC 配方名称关联与生产可用性

- 普通业务界面只选择和显示 PLC 配方名称，不显示或手工编辑数字配方号；实际槽位号由“地址维护 -> 配方名称地址”映射，并随程序隐藏保存。
- 单工位程序必须配置工位 1 配方；双工位程序允许一侧选择“不适用”，但不能两侧同时不适用。双工位同工单生产时，两个工位都必须配置有效关联。
- 工位 1 与工位 2 的配方关联相互独立。生产开工、PLC 下发和回读校验始终按目标工位使用本机程序记录中的隐藏配方号，不复用另一工位值。
- MES 下载的程序不会携带本机 PLC 配方映射；下载后需在程序管理中选择对应工位的 PLC 配方名称并保存，完成前该程序不会出现在相应工位的可生产列表中。
- PLC 调整配方槽位顺序、名称或地址后，系统不会按名称自动迁移历史关联。请先在地址维护确认新映射，再到程序管理重新选择名称并保存。
- 数字配方号仅在地址维护映射和日志诊断中保留，供配置确认和现场排障使用。
- 每个工位最多配置 64 个 PLC 配方名称槽位；配方名称刷新有单工位 10 秒时限，读取失败或超时不会阻塞程序管理页面的新增、删除和批量清理操作。

## 开工产品工号编辑

- “产品工号”是可编辑下拉框，在线和离线都允许操作员改写，开工按界面上显示的工号上报。下拉选项来自本机程序库中当前工位可生产程序的工号；也可以直接手工输入程序库里没有的现场工号。
- 离线模式下产品工号初始为空，不会默认选中第一个选项，必须由操作员选择或输入后再开工；留空开工时按所选加工程序关联的工号上报。
- 离线模式下“程序名称”与产品工号是相互关联的一组录入项，两者保持同一空值状态：程序名称同样初始为空、不默认选中第一个程序；转入离线时两者一起清空；把产品工号清成空白时程序名称一并清空，避免工号已被清掉却仍按残留程序的工号开工。未选择程序名称就点开工会提示必须选择程序。
- 需要手工输入程序库里没有的现场工号时，先选好程序名称再改工号：把工号改成另一个非空值不会影响已选程序，只有清成空白才会一起清空。
- 在线模式下产品工号先由 MES 工单回填，操作员可在开工前改写，本次开工按改写值上报，不会写回 MES 工单本身。重新查询到新工单时回填工单值并覆盖改写。
- 已开工、任务运行中或工位只读时产品工号不可编辑。
- “工序名称”与其他开工字段同规则：未开工时可编辑（在线态需工单已加载，离线态直接可录入），一旦开工或任务运行中即变为只读。
- 离线模式下“员工号”开放给现场操作员编辑，不预填程序登录账号，也不受“系统设置 -> 操作员弹窗输入”影响；转入离线时会清空在线阶段校验过的员工信息。留空点“本地工单”会提示员工号必填。离线无法向 MES 校验身份，员工号按录入值原样落库和补传，员工姓名、部门和班组保持为空；离线完工沿用开工时录入的员工号，不再二次录入。
- 离线模式下工序号、工序名称和工单数量都不预填默认值，转入离线时一并清空，全部由操作员录入。工序号留空点开工会提示工序号不能为空；工序名称和工单数量允许留空，留空时按空值和 0 落库并上报，任务记录、XLSX 报表表头和生产指标“达成率”会相应显示为空。
- 程序名称列表是否按产品工号收窄，由“生产监控 -> 按工号筛选”决定，离线与在线语义一致：启用时只显示该工号的程序；未启用时显示全部可生产程序，便于一款产品借用另一款工号的程序生产。
- 在线模式启用该设置后，程序列表改为直接让 MES 按工号查询，请求形如 `<MES地址>/api/ExpProgram?deviceId=62131399173-2&productNum=115#K-3`；工号原样传出，`#` 属于工号本身，不做替换（URL 中按 HTTP 规范编码为 `%23`）。未启用时不携带 `productNum`，仍取回该设备的全部程序。MES 返回后客户端仍按工号兜底筛选，兼容忽略该参数的旧版 MES。
- 未启用筛选时选中工号仍会跳转到该工号的首个程序，之后可自由改选其他工号的程序。
- 同一工号存在多个程序时，列表按“程序名称”区分，可继续在程序名称下拉中选择具体程序。
- 双工位分别记忆各自录入的工号；切换工位或退出离线模式时该记忆自动清除。

## 系统设置设备管理锁定

- PLC 设备状态本身不控制“系统设置 -> 设备管理”的可编辑状态；即使 PLC 状态为 `1`，只要当前软件运行态没有活动生产任务，设备管理仍可编辑。
- 任一工位在线或离线开工后，当前运行态存在尚未完工的 `ActiveTask` 时，整个设备管理区域不可编辑；暂停中的活动任务仍保持锁定，完工后自动恢复。
- 数据库中的历史未完工记录不会单独锁定设备管理区域；软件重启后，只有当监控流程把任务恢复为当前运行态任务时才重新锁定。
## 日志管理显示

- 设备状态日志表格不显示“来源”和“工位”，生产流程日志表格不显示“步骤”，设备日志表格不显示“工位”；这些字段仍保留在右侧详情中并继续参与关键字搜索。
- 生产流程摘要统一使用集中维护的中文文本；旧 JSONL 中已存在的配方号调和、设备模式调和和工单状态英文摘要会在界面显示时转换为中文，不重写历史文件。

## MES 在线状态检测

- MES 在线状态由专用的在线检测接口（默认路由 `api/sys`，GET）判定，按系统设置中的「心跳间隔（秒）」轮询，默认 5 秒，可填 1-300 秒；返回状态为 `S` 视为探测成功，连续 3 次探测失败（含超时、非 2xx、响应无法解析）才确认离线，任意一次成功会立即清零失败次数并保持或恢复在线。
- 自动 MES 在线心跳使用独立的 3 秒超时且不写入 MES 交互日志，避免在线探测失败/恢复干扰业务请求排查；连续 3 次失败后的 MES 断线和恢复由设备日志记录。生产模式和上传状态只使用连续失败确认后的连接状态，单次或两次偶发失败不会切换离线。
- 设备校时接口（默认路由 `api/ServerTime`）只在程序启动时调用一次，不再承担在线探测职责。
- 系统设置页的「测试连接」按钮同样访问在线检测接口，因此提示仅显示是否连通，不再返回服务器时间。

## 中心服务器同步与日志

- 设备端按系统设置中的心跳间隔先向中心服务器发送 `heartbeat`。中心服务器不可达时，只记录首次“心跳失败”；持续失败不重复刷日志，恢复连接时再记录一条“心跳成功”。
- 中心服务器连接成功后，设备启动首次同步会发送一次完整 `telemetry`；此后只有 PLC 连接、设备状态、报警、工单、工单数量、产品信息或当日产量等看板字段发生变化时才发送，不再按固定时间重复推送未变化快照。
- 工位快照同时推送工单数量（MES 生产数量）与当日产量，中心看板据此显示「工单数量」和「达成率」。达成率口径为合格数 ÷ 工单数量，与设备端监控页一致，不含不良品，超产时会大于 100%；未选工单或工单数量为 0 时显示 `--`。
- 同一设备两个工位使用同一工单时，工单数量只计一次，避免达成率分母翻倍；两个工位分属不同工单时，工单数量按工单分别累加。
- 断线期间仅保留最新快照。恢复连接后，如果快照相对最后一次成功同步确有变化，会在心跳成功后补发一次；未变化时只恢复心跳，不重复发送设备状态。
- 设备端和中心服务器统一使用三类消息：`heartbeat=心跳`、`telemetry=设备状态`、`product-report=产品数据`。心跳只维护在线时间，设备状态负责更新完整工位快照。

## 生产报表与补传

- “待上传数据 -> 过程参数”页签及工单总览中的过程参数状态只展示、统计目标为 MES 的过程参数；CentralServer 数据仍由其独立后台链路处理，不混入 MES 补传视图。
- 工单完工后本地 XLSX 报表会先生成；只要 XLSX 生成成功，就会进入“待上传数据 -> 报告文件”任务队列并参与 MES 上传/补传，不再依赖产品明细行或 `ReportEnable` 输出项作为入队前置条件。
- 若历史工单已生成 `Biz_ProductionReportFile` 记录但缺少对应 `ReportFile` 上传任务，进入报表待上传页、全部重试或自动补传前会自动补齐任务；用户已经手动删除或已经上传成功的任务不会被恢复。
- 没有任何产品生产数据时，报表仍会按公共字段生成并上传；如果 MES 或文件路径失败，失败信息保留在待上传数据中供手动重试。
- 设备端与中心服务器生产报表统一使用客户参考模板：任务表头依次展示流转卡号/规格/产品型号、产品工号/批次/部件名称、部件图号/工序名称/工序号、工单数量/合格数量/操作人员、开始时间/结束时间；明细列按“产品编号 -> 检测面或焊点号 -> 动态测试值 -> 检测结果或焊点结果 -> 产品结果”排列。整件检测默认显示“检测面/检测结果”，产品工艺自定义表头仍可覆盖。

## 设备状态日志与补传

设备状态固定使用 `0=停机`、`1=开机`、`4=异常`、`5=异常恢复`、`6=程序执行开始`、`7=程序执行结束`。设备状态 JSONL 是唯一事实来源，文件位于配置日志根目录下的 `DeviceStatus/*.jsonl`；日志管理、当前状态查询和待上传数据中的设备状态都从这里读取。

- 状态变化会先写入 JSONL，落盘成功后才会刷新界面、上传 MES 或建立补传任务。
- 待上传数据页签的数据库和 JSONL 查询在后台执行；页签切换复用固定表格列，设备状态读取会复用未变化文件的最新快照，避免重复扫描历史 JSONL。单个损坏记录会被跳过并写入异常日志，不会阻塞页面重绘。
- PLC 报警判定可在“系统设置 -> PLC 配置”选择“仅报警地址”或“设备状态异常且报警地址触发”；旧配置默认使用后者，保存后下一轮采集立即生效。报警读取关闭时冻结当前报警周期，重新启用后再按真实读取结果处理。
- 每个报警地址独立形成“异常触发 -> 异常恢复”链路；多个地址可同轮触发或恢复。部分恢复后会按 `5...5 -> 4` 的顺序重申一个仍有效报警，保证 MES 最终状态仍为异常。共享报警设备级只记录一次（`StationNo=0`），但两个工位监控页都会显示。
- 报警地址属于整台设备，地址维护页不再配置程序工位；历史 `StationNo` 字段仅保留数据库兼容，读取和保存时统一按设备级 `0` 处理。报警内容中的“左/右”等机构描述保持原文，不映射为程序工位。
- MES 与本地 JSONL 的 Remark 使用统一格式：单工位程序边界为 `程序执行开始`/`程序执行结束`，双工位按系统设置映射为 `左工位：程序执行开始`/`右工位：程序执行结束`；异常和恢复统一为 `异常：报警内容`/`异常恢复：报警内容`，不包含报警地址或 PLC 报警工位。设备状态日志表格不显示报警地址和内容，但仍可按这两项搜索并在详情中查看。
- 程序启动时会先把当前 `1=开机` 写入 JSONL，再在后台扫描全部日期文件，按发生时间从旧到新补传 `Pending/Failed` 状态；旧记录上传失败时会暂停本批后续状态，避免新的开机或运行状态越过旧 `0=停机`。该过程不阻塞登录界面。
- MES 断线重连后会复用同一设备状态补传流程，并继续按发生时间顺序处理全部日期 JSONL。
- 关闭窗口时界面立即退出；后台进程会在一个 MES 超时时间内（最少 3 秒，默认 10 秒）同步等待本次 `0=停机` 上报。成功记录为 `Uploaded`，失败记录为 `Failed`，超时前已落盘但未完成的记录保留为 `Pending/Failed`，下次启动继续补传。
- 删除某个日期文件或整个 `DeviceStatus` 目录后，刷新或重新进入日志管理/待上传页面即可移除对应记录；其中未成功上传的状态不再参与单条或批量补传。
- 已成功上传到 MES 的结果不会因为删除本地 JSONL 而撤销，已有上传任务历史也不会回退为待上传。
- JSONL 首次落盘失败时不会上传该状态，也不会生成补传任务。请到“日志管理 -> 程序异常日志”检查磁盘空间、日志目录和写入权限。
- 升级不会删除旧的 `Biz_DeviceStatusLog` 物理表，但程序不再创建、读取或写入该表。

### 本次变动的意图与影响

`v2.2.0` 不是单纯的报表字段调整，而是对整件检测设备“采集完成 -> 结果判定 -> 本地历史 -> 报表 -> MES”的数据口径进行统一：

- **为什么要改**：PLC 会保存四个面的原始检测值，但客户只需要 A/B 两面结果；同时，部分现场需要由程序按产品程序中配置的最大允许值判定，而不能继续直接采用 PLC 最终结果。
- **哪些设备受影响**：只有系统设置中“过程参数设备类型 = 整件系统-检测设备”，且产品工艺面数量为 4 的产品进入本次 A/B 和程序判定逻辑。电磁设备、整件点焊设备、非四面工艺以及 `PLC读取` 模式保持原有结果和输出行为。
- **故意保留什么**：面 1、2、3、4 的原始检测值、PLC 原始面结果和 PLC 原始产品结果仍保留在本地记录的原始数据中，用于数据管理、追溯、看板和故障分析；A/B 派生结果只用于报表和 MES 输出，不反向覆盖四面原始数据。
- **外部影响**：整件检测产品的 MES 过程参数由原来的四条面数据改为 `SideNo=A/B` 两条数据；报表由四面明细输出改为 A/B 两行。该协议和报表行为属于有意的不兼容变更，部署前必须完成现场配置和接口联调。

### 四面原始数据与 A/B 输出口径

整件检测设备且产品工艺面数量为 4 时，系统仍从 PLC 采集并内部保存面 1、2、3、4；数据管理和中心看板按“保存历史”显示四面明细。XLSX 报表与 MES 过程参数改为每个产品输出 A、B 两行：

- A 面对应 PLC 面 2、4；B 面对应 PLC 面 1、3。面号必须由 PLC 返回并规范为唯一的 `1、2、3、4`，不按采集顺序猜测。
- 对称度等普通数值项目：A=面 2、4 平均，B=面 1、3 平均。
- 名称严格为“高度”或“宽度”的项目：直接取面 1～4 原始实测值的最大值，A/B 两行发送同一个最大值；XLSX 中对应列跨 A/B 两行纵向合并。
- A/B 结果按配对面从严合并：配对两面均 OK 才为 OK，任一面 NG 则为 NG；平均值回落到限值内也不能覆盖原始面的 NG。
- 聚合值使用 `decimal` 计算；小数位来自测试项实际值表达式的 `_小数位`，是否裁切或四舍五入复用系统设置中的“PLC字符串数值处理”。

### 检测结果来源配置

系统设置中的“检测结果来源”仅对整件检测设备生效：

- `PLC读取`：默认值，保持兼容行为；PLC 单面结果和 PLC 产品结果继续作为正式结果。
- `程序计算`：PLC 单面结果只作为“该面已完成测试”的门禁，不直接作为最终显示或落库结果。程序使用本次开工时固化到 `BizWeldTask.ProgramContentSnapshot` 的“最大允许值”逐面计算：实际值小于或等于最大允许值为 OK，实际值大于最大允许值为 NG；单面结果再用于 A/B 配对和产品结果汇总。产品结果按 A/B 合并值判定，其中 `高度`、`宽度` 的合并值为 `0` 或负值时判 NG——视觉检测失败约定回传 `0`，合并后仍为 `0` 说明参与聚合的面全部没检测成功。该零值检查只作用于合并值，单面回传 `0` 不会把该面判成 NG；`对称度` 真值可能为 0，不做零值检查。
- 程序计算模式下，未完成面、结果未知、焊前 NG 或读取失败时不读取对应测试值；实时预览继续显示 `--`，避免把 PLC 清零残留值当作新测试值。真实的 `0/0.00` 在 PLC 完成结果有效时仍是合法测试值。
- 程序管理和开工确认中的“设定值/标准值”列已改为“最大允许值”，其数值会随开工固化到任务快照；开工后再修改程序，不改变当前任务的判定基准。
- 缺少最大允许值、最大允许值或实测值不是数字、方案存在重复测试项名称时，本件采集失败且不落库、不刷新报表、不创建 MES 数据，并沿用现有 PLC 失败反馈要求重新采集；错误日志会包含产品号、面号和测试项。
- 存在任意未完工任务时不能切换结果来源，必须完工后再调整，避免同一任务前后使用两套判定规则。

### 部署前配置迁移与回退边界

升级不是名称匹配式自动迁移，程序不会自动删除现场测试项、修改 MES 字段名或改写历史数据。部署前请按以下顺序人工确认：

1. 在 S01～S04 中保留“对称度、高度、宽度”等原始测试项，并按需要分别勾选“启用采集、保存历史、写入报表、上传 MES”。
2. 在原始测试项上配置 `Symmetry`、`Height`、`Width` 等大小写不敏感且唯一的 MES 字段名；A/B 聚合只支持实际值，不能为上限、下限或测试项结果开启报表/MES。按面聚合策略靠测试项名称精确匹配：取四面最大值的必须严格命名为“高度”，只取 A 面的必须严格命名为“宽度”，改名会让这两条策略静默失效并退回普通 A/B 配对聚合。
3. 从方案明细中移除“A面对称度、B面对称度、A面高度、B面高度”等重复派生项；确认没有其他方案引用后，再人工删除对应字典项。
4. 确认产品工艺面数量为 4，PLC 面号实际返回唯一的 1、2、3、4；A/B 聚合源必须使用按面偏移的相对地址，固定绝对地址会被拒绝，避免四面重复读取同一个寄存器。
5. 先完成配置调整，再启动新版本；配置完成后先用 `PLC读取` 做现场基线核对，再按需要切换到 `程序计算`，并验证零值、超限值、焊前 NG、PLC 清零和四面缺面场景。
6. 如需回退结果判定，必须先完工当前任务，再将“检测结果来源”切回 `PLC读取`；回退只影响后续任务，不回写已采集历史，也不把已上传 MES 的 A/B 数据恢复成旧四面协议。

缺面、重复面、未知面结果、非数字值、重复 MES 字段或错误聚合配置会使本次产品采集失败并要求 PLC 重采，不会保存半成品记录或生成不完整的报表/MES 数据。

## 版本管理

软件版本统一配置在 `Directory.Build.props`：

```xml
<Version>2.14.0</Version>
<AssemblyVersion>2.14.0.0</AssemblyVersion>
<FileVersion>2.14.0.0</FileVersion>
<InformationalVersion>2.14.0</InformationalVersion>
```

建议使用语义化版本：

- 主版本：架构或兼容性发生重大变化。
- 次版本：新增功能。
- 修订号：缺陷修复或小范围优化。

发布新版本时：

```powershell
git tag -a v2.14.0 -m "Release v2.14.0"
git push origin main
git push origin v2.14.0
```

## 注意事项

- 不要提交本机真实 `appsettings.json`、数据库密码、现场 MES 地址、现场 PLC 地址等敏感配置。
