# AutoWeldSystem

自动点焊系统上位机软件，用于对接 PLC、MES 和本地程序管理流程。当前版本：`v3.0.0`。

各版本的行为变化记录在 [CHANGELOG.md](CHANGELOG.md)，也可用 `git tag -n99` 查看对应版本的发布说明。

## 功能概览

- 生产监控：工单信息、程序信息、PLC/MES 连接状态、设备状态、生产指标实时显示；采集预览和产品历史仅在开工后显示，无运行任务且无待开工工单或离线草稿时清空工单信息；右侧区域按可用高度与 DPI 自动切换紧凑布局，仅在极低高度下纵向滚动。程序配置一个采集点且产品只有一条记录时，产品历史直接显示为单行；多采集点或重复测试仍保留树形明细。
- 产品重测：PLC 计数模式下仅整件检测设备支持。PLC 触摸屏点击“重测”后不更新产品编号，上位机识别为重测并就地覆盖该产品的测试值、结果和采集时间，产品历史、报表、MES 过程参数和中心看板均更新为最新一轮结果，重测记录写入操作日志；重测不清除已标记的试焊件（`v2.26.0` 修复）。
- 产品重焊/删除：自 `v2.26.0` 起，系统设置「产量统计来源」为**程序统计**时，生产监控页产品历史右键可对**未上传**产品执行「重焊」（整件检测显示为「重测」）、「删除」和「撤销删除」，详见[产量统计来源与程序计数模式](#产量统计来源与程序计数模式)。
- MES 交互：员工校验、工单获取、开工上报、完工上报、设备编号同步、程序上传/下载。
- 过程参数上传：测试项字典配置单位后，实际值、上限和下限按“值 单位”上传，结果字段保持原值；试焊件字段 `IsTest` 使用 JSON 布尔值 `true/false`；整件检测四面工艺在本地保留 1～4 面原始数据，上传 MES 时输出 `SideNo=A/B` 两条数据，对称度按 A=面2/4、B=面1/3 各取最大值，高度取四面最大值并在 A/B 两条数据中重复发送，宽度只取 A 面（面2、面4）最大值、B 条数据的宽度字段传空字符串；`Result` 自 `v2.21.0` 起统一填**产品结果**（A/B 两条同值，行级 OK/NG 已取消），不发送 `Type`、`TouchNo` 和 `IsTest`。数值字段先按“判定与上报小数位”设置格式化再追加单位。
- PLC 监控日志：周期读取设备状态、实际数量、合格数量和失效数量失败时记录为“PLC 业务信号读取失败”；“生产数据采集失败”仅表示开工后的产品数据就绪信号触发实际产品数据采集失败；报警地址读取失败单独记录。PLC 心跳支持独立配置监测频率、心跳超时时间和通讯超时，并在状态提示中显示采样间隔、通讯锁等待和 PLC 读取耗时。
- PLC 报警通知：多条 PLC 报警在屏幕左下角以 Notification 完整展示。报警地址属于整台设备，不区分工位，因此通知标题不带工位号，同一个屏幕上双工位也只弹一张卡片。启用双工位时主屏和扩展屏各显示一张内容相同的卡片，可分别关闭。通知支持手动关闭，报警恢复后自动关闭；右侧异常摘要点“清除”会同时关闭通知卡片并按当前报警内容标记为已读，报警内容变化或恢复后重新弹出。
- 设备状态上报：JSONL 本地记录与 MES `Remark` 使用同一格式；单工位使用“开机/停机/程序执行开始/程序执行结束”，双工位的程序边界使用系统设置映射生成“左工位：程序执行开始”等文本；报警地址的 PLC 工位不进入备注，异常统一为“异常：报警内容”或“异常恢复：报警内容”。
- 实时预览：每个面/焊点先读取 PLC 拍照结果或焊点结果作为完成门禁，只有 `OK/NG` 才显示该面的测试值；未测试、清零残留、读取失败和焊前 NG 显示 `--`，真实的 `0/0.00` 在有效结果下正常显示，下一次 PLC 清零后不会保留上一帧数据。整件检测自 `v2.21.0` 起取消逐面判定：面结果寄存器恒为视觉的检测完成信号，逐面视图只显示实测值不做判定，产品是否合格只由 A/B 合并值决定。视觉检测失败或未识别时固定回传 `1`，逐面视图原样显示 `1.0000` 便于与视觉侧核对。
- 程序管理：本地程序版本管理、提交记录、MES 同步状态，以及按工位选择 PLC 配方名称并隐藏保存槽位配方号；每个程序必须填写一个正整数焊点数量（整件检测界面显示为面数量），双工位共用并随程序内容同步 MES；保存、校验和同步结果使用非阻塞全局提示，不影响继续操作主界面；删除确认框绑定主窗体显示，始终位于主程序之上。
- 生产监控：产品工号筛选程序与双工单切换入口位于工单信息区，复选框悬停可查看完整说明；单工位时双工单开关自动禁用。`UseProductNumberFilter` 同时影响在线和离线开工的程序列表筛选；产品工号与程序名称自 `v2.27.0` 起互不联动，详见「开工产品工号与程序名称」。整件检测设备在实时预览上方显示「设定值」，即本次开工固化的程序上下限（如 `10≤高度≤12.5`），与产品判定同源；宽度不足时省略，悬停可看完整内容。
- 系统设置：应用全部优先保存本地配置；仅在设备编号、名称或相关服务地址发生变化时后台同步设备信息到 MES，保存和同步结果使用非阻塞全局提示。同步报文中的本机 IP 自 `v2.21.1` 起按可信度依次选取：到 MES 基地址的路由源地址、“状态地址”中已配置的本机 IP、主机名解析结果，避免多网卡工控机报出与 MES 不通的虚拟网卡地址；三者都不可用时上报空值。整件检测固定走程序判定，“检测结果来源”“A/B配对聚合方式”“整件检测逐面结果显示”“整件检测四面合并显示”四项配置自 `v2.21.0` 起移除；合并视图改由生产监控页「合并显示」复选框控制，默认开启并记住上次选择，仅对拥有对应权限的角色显示（默认仅管理员）。PLC 一组的“判定与上报小数位”（默认 2 位）同时控制**产品判定**、合并视图、上传给 MES 的 XLSX 报表和 MES 过程参数，四者必须同源——操作员在合并视图看到的数值就是判定所用的值；截断还是四舍五入沿用同组的“PLC 数值格式处理方式”。逐面视图、数据管理页“导出测试数据”、历史数据列表和中心看板不受该项影响，始终沿用测试项配置的采集小数位。
- 中心服务器同步：中心服务器未启动或网络不可达时仍按配置周期探测，连接类失败只在服务器日志记录首次、每 10 分钟持续故障摘要及恢复状态，不写入程序异常日志；服务端已应答的业务失败也只保留在服务器日志。
- 待上传数据：工单信息页签持续显示未完工任务及开工、过程参数、xlsx 报表和完工上报四阶段状态，直到任务完成且相关上传阶段处理完毕；生产期间可增量生成本地 XLSX，设备端和中心服务器报表会在实际值、上限、下限列标题后追加测试项单位，结果列不追加单位；报告文件必须等待 MES 完工上报成功后才允许上传，启动补传和手动重试同样遵守该顺序；切换各上传页签时会刷新绑定字段元数据，避免有记录但单元格空白。
- 数据管理：使用通用“测试数据”页签兼容点焊与检测设备，按产品展开测试记录树；「采集数据」页签展示原始焊点行（含已删除产品与「已删除」列），自 `v2.26.0` 起受页签权限 `tab.data.collection-data` 控制，默认仅开发者可见，管理员可在角色权限中授予；按任务绑定程序和工位解析对应方案，方案明细中勾选“本地保存”的动态测试项会写入本地历史，勾选“转发看板”的动态测试项在启用中心同步时转发到中心服务器看板，两者互相独立，写入报表或过程参数独占字段不会展示；原始数据仅供内部流程使用，不在界面展示；报告文件入口独立保留。任务程序快照配置一个采集点且该产品只有一条测试记录时，直接显示为单行；多采集点或重复测试仍保留产品到测试记录的树形结构。支持按产品结果筛选全部/OK/NG 数据，点击动态测试列按产品升降序排列。导出沿用上传报表的**客户模板版式**写入用户指定的 XLSX 路径，但内容定位为后台查阅的明细数据：末列是产品结果、不含上传状态；导出始终覆盖整个工单，不受产品结果筛选和分页影响；动态列覆盖「本地保存」和「上报」两个通道，历史记录中可见的动态测试项全部导出，小数位沿用采集小数位；整件检测四面工艺**不做 A/B 聚合**，保留逐面原始记录和采集点表头。测试数据按产品行分页，默认每页 20 个产品，可切换 20/50/100；产品节点默认折叠，工具栏可一键展开或折叠全部测试记录。历史工单支持多选删除、清理上传失败工单和按筛选日期区间批量清理，删除会级联清除该工单的采集记录、上传任务、报表记录以及磁盘上已生成的 xlsx 报表；生产中和已暂停的工单会被自动跳过，需要“删除历史数据”权限，删除结果写入操作日志。
- 地址维护：维护固定业务信号对应的 PLC 实际地址，并按工位配置/预览 PLC 配方名称与数字槽位的映射；产品工艺不再维护焊点数量，地址预览按同产品有效程序中的最大数量展开，没有有效数量时只显示第 1 点模板并提示；PLC 实际/预设数量表达式及数量表头继续保留。方案明细的五个通道互相独立——左侧树的“实时预览”只控制实时预览表格显示，右侧表格的“本地保存”“转发看板”“写入报表”“过程参数”分别决定本地历史、中心看板、上传报表和接口上传，任一勾选即可保存；各维护页签可按角色独立授权。测试项字典的偏移量表达式支持减法计算式 `(134-84):S-7_3`，用于 PLC 无对应寄存器但可由两个已有偏移相减得出的数值（如焊接前后位移量），只支持一次减法和两个整数相对偏移，不参与本地 OK/NG 判定。
- 测试项字典的实际值、上限、下限和结果表达式同时支持相对地址与绝对地址：相对地址如 `14:F-0_2` 按测试项基地址和焊点偏移计算，绝对地址如 `DB97.26:F-0_2` 直接读取指定 PLC 地址，不叠加测试项基地址和焊点偏移。
- 日志管理：MES 交互日志表格按发送时间、接口路径、请求原因、方法、HTTP、结果和耗时展示，完整请求地址及请求/响应正文保留在详情中；MES 交互、生产流程、程序异常、设备、设备状态和服务器日志页签可按角色独立授权。
- 权限管理：本地用户、角色、页面、页签和按钮权限控制。启动权限初始化会清理已废弃的“导出数据”权限及其角色关联；旧库首次引入日志/地址页签权限时，会为已有对应页面权限的非开发者角色一次性补齐全部页签，后续保留管理员手工调整结果。
- 国际化：支持简体中文和英文界面切换。

## 技术栈

- .NET 8 Windows Forms
- AntdUI
- Microsoft.Extensions.Hosting
- SqlSugar + MySQL
- HslCommunication

## 项目结构

```text
AutoWeldSystem
├─ AutoWeldSystem.Core       # 常量、DTO、接口、模型、权限定义和多语言资源
├─ AutoWeldSystem.Data       # SqlSugar 数据库上下文和数据库初始化
├─ AutoWeldSystem.Services   # MES、PLC、程序管理、日志、权限等业务服务
├─ AutoWeldSystem.UI         # WinForms 界面、窗体、控件和应用入口
├─ AutoWeldSystem.Libs       # 本地 DLL 依赖
├─ Directory.Build.props     # 全局程序集版本配置
└─ AutoWeldSystem.sln
```

## 环境要求

- Windows 10/11
- Visual Studio 2022
- .NET 8 SDK
- MySQL 5.7/8.0

项目引用了本地依赖 `AutoWeldSystem.Libs/HslCommunication.dll`，请保留该目录结构。

## 本地配置

真实配置文件 `AutoWeldSystem.UI/appsettings.json` 已加入 `.gitignore`，不会提交到仓库。首次拉取后可从示例文件复制一份：

```powershell
Copy-Item AutoWeldSystem.UI/appsettings.example.json AutoWeldSystem.UI/appsettings.json
```

然后按本机 MySQL 环境修改连接字符串。

当前数据库上下文会在启动时执行 CodeFirst 初始化，创建系统需要的表结构。默认管理员账号和权限数据由服务初始化逻辑维护。

首次初始化会创建三个内置账号：

| 账号 | 角色 | 初始密码 |
| --- | --- | --- |
| `admin` | Administrator | `123456` |
| `operator` | Operator | `123456` |
| `readonly` | Readonly | `123456` |

现场部署后请及时修改默认密码。

## 发布

在仓库根目录执行以下命令，`-o` 指定产物目录，发布完成后进入对应目录取文件。

### 非自包含（默认，目标机需预装 .NET 8 运行时）

```powershell
dotnet publish AutoWeldSystem.UI\AutoWeldSystem.UI.csproj -c Release -r win-x64 --self-contained false -o artifacts\UI-win-x64
dotnet publish AutoWeldSystem.CenterServer\AutoWeldSystem.CenterServer.csproj -c Release -r win-x64 --self-contained false -o artifacts\CenterServer-win-x64
```

### 自包含（目标机无法安装运行时时使用）

```powershell
dotnet publish AutoWeldSystem.UI\AutoWeldSystem.UI.csproj -c Release -r win-x64 --self-contained true -o artifacts\UI-win-x64-selfcontained
dotnet publish AutoWeldSystem.CenterServer\AutoWeldSystem.CenterServer.csproj -c Release -r win-x64 --self-contained true -o artifacts\CenterServer-win-x64-selfcontained
```

### 产物位置

产物固定输出到仓库根目录下的 `artifacts\`：

| 内容 | 产物目录 | 启动文件 |
| --- | --- | --- |
| 上位机主程序（非自包含） | `artifacts\UI-win-x64\` | `AutoWeldSystem.UI.exe` |
| 上位机主程序（自包含） | `artifacts\UI-win-x64-selfcontained\` | `AutoWeldSystem.UI.exe` |
| 中心服务器（非自包含） | `artifacts\CenterServer-win-x64\` | `AutoWeldSystem.CenterServer.exe` |
| 中心服务器（自包含） | `artifacts\CenterServer-win-x64-selfcontained\` | `AutoWeldSystem.CenterServer.exe` |

现场部署时把整个产物目录复制到工控机，运行其中的 `.exe` 即可。

### 目标机运行时要求

非自包含产物体积小、运行时可独立打补丁，但**目标工控机必须预装 .NET 8 运行时**：

- 上位机主程序 UI 需要 **.NET Desktop Runtime 8**（WinForms 依赖）。
- 中心服务器 CenterServer 需要 **ASP.NET Core Runtime 8**。
- 同机部署两者时装 Desktop Runtime + ASP.NET Core Runtime 即可，均为 x64。
- 现场无法安装运行时或无外网时改用自包含发布，产物体积明显增大，但不依赖预装运行时。

发布产物目录 `artifacts\` 已在 `.gitignore` 中忽略，不进入版本库。UI 的 `appsettings.json` 会随发布输出，现场需按实际 PLC、MES、MySQL 参数单独维护，不要把现场配置提交回仓库。

## 运行

使用 Visual Studio 打开 `AutoWeldSystem.sln`，将 `AutoWeldSystem.UI` 设置为启动项目后运行。

启动前请确认：

- MySQL 服务可访问。
- PLC IP、端口、协议类型符合现场配置。
- MES 地址、设备编号、日志路径、数据路径可在系统设置界面维护；MES 各接口路由、超时时间和在线检测心跳间隔也在同一页面配置。
- 修改设备编号时会先使用最后一次成功同步的旧编号更新 MES；如果 MES 明确返回旧设备不存在，系统会询问是否将新编号作为新设备注册，只有确认且注册成功后才更新本地已同步编号。
- PLC 地址在地址维护界面中填写完整。

## 程序管理界面操作

- 左侧列表按程序平铺显示，同一产品工号的多个程序各占一行并重复显示产品工号；首列按当前筛选结果显示程序连续序号，程序名称和同步状态分列显示，不再展示本地版本号或折叠箭头。
- 列表按程序更新时间全局倒序排列，更新时间相同时按本地程序 ID 倒序，最近修改的程序排在最前；同一产品工号的程序允许跨页。
- 列表底部为分页控件，默认每页 20 个程序，可切换 20/50/100。设备可存放上百个加工程序，分页后列表不会一次铺满。序号在分页前生成，因此翻页后序号仍然全局连续（第 2 页从 21 开始）。
- 工具栏右侧是查询控件，左侧“刷新”按钮、中间关键字输入框、右侧“搜索”按钮合并在一起。输入关键字后按回车或点“搜索”执行筛选；点“刷新”或清空关键字后再次搜索，会重新载入程序列表和 PLC 配方名称并恢复完整列表。关键字不再逐字符触发筛选。
- 搜索会回到第 1 页。保存、另存为、同步、删除和刷新后列表会自动翻到正在编辑的程序所在页并保持选中；手动翻页只切换可见页，不改变右侧正在编辑的内容。
- 工具栏“保存后立即同步”复选框控制保存和删除后是否马上向 MES 同步，默认勾选，行为与此前一致。
- 焊点数量、工位配方名称和限值表格集中在“程序内容”区域；单工位隐藏工位 2 配方行时不挤压程序身份编辑区。查询控件在自动布局下会按提示文字补足首选宽度。
- 右侧当前程序状态仅显示“当前：已同步 / MES程序ID”或“当前：未同步”；本地新建状态继续显示“当前：新建本地程序”。
- 点击任意程序行直接切换右侧编辑内容；保存、另存为、同步、删除和刷新后会自动定位到对应程序所在页并保持选中。
- 同一工号下可以有多个程序，用“另存为新程序”按当前内容新建一条，流水号自动取该工号下的下一个可用值。
- 在线、离线、配方匹配和程序列表使用轻量程序快照；快照只从程序内容派生可空焊点数量，不向界面传递完整 JSON，程序详情仍在选中或开工时按需加载。
- 产品工号、部件图号、工位配方名称和焊点数量为必填项，标签前带红色星号；焊点数量必须是大于 0 的整数，整件检测设备界面显示为“面数量”。留空或格式错误时会在字段附近标红并禁止保存。
- 焊点数量作为 `ProgramContent` 保留键 `"焊点数量":"4"` 保存并同步 MES，一个程序的两个工位共用同一数量。该键不会进入测试项表格、设定值摘要或产品判定参数。
- 程序名称由工号、部件图号、流水号和程序备注拼成。部件图号只去掉首尾空白；程序备注不做裁剪或字符过滤，例如备注 `1-3+` 会完整出现在程序名称中；工号仍去掉 `#`。同工号下若流水号和程序备注都相同会产生重名，保存时会被拒绝，需调整流水号或程序备注。

**数量字段升级注意：** 不自动把产品工艺旧 `TouchCount` 列迁入程序，也不在运行时回退该列。自 **3.0.0** 起，MES 下载在本地写入前要求新格式且包含有效焊点数量，缺失或非法时不覆盖本地程序；请在程序管理中逐个补齐并重新同步。旧任务若缺少有效数量，既有的采集、历史查看、导出、报表和补传校验仍会拒绝，系统不隐式推断；若数量有效但限值还是旧格式，可继续按原记录查看，不得恢复生产或生成新的正常输出。升级前应在旧版完成任务及待上传数据处理，详见[程序上下限与严格 JSON](#程序上下限与严格-json300)。

## PLC 配方名称关联与生产可用性

- 普通业务界面只选择和显示 PLC 配方名称，不显示或手工编辑数字配方号；实际槽位号由“地址维护 -> 配方名称地址”映射，并随程序隐藏保存。
- 单工位程序必须配置工位 1 配方；双工位程序允许一侧选择“不适用”，但不能两侧同时不适用。双工位同工单生产时，两个工位都必须配置有效关联。
- 工位 1 与工位 2 的配方关联相互独立。生产开工、PLC 下发和回读校验始终按目标工位使用本机程序记录中的隐藏配方号，不复用另一工位值。
- MES 下载的程序不会携带本机 PLC 配方映射；下载后需在程序管理中选择对应工位的 PLC 配方名称并保存，完成前该程序不会出现在相应工位的可生产列表中。
- PLC 调整配方槽位顺序、名称或地址后，系统不会按名称自动迁移历史关联。请先在地址维护确认新映射，再到程序管理重新选择名称并保存。
- 数字配方号仅在地址维护映射和日志诊断中保留，供配置确认和现场排障使用。
- 每个工位最多配置 64 个 PLC 配方名称槽位；配方名称刷新有单工位 10 秒时限，读取失败或超时不会阻塞程序管理页面的新增、删除和批量清理操作。

## 流转卡号输入（扫码与手动）

流转卡号支持**扫码枪和键盘手动输入**，两者共用同一个输入框、走同一条确认路径（扫码枪本质就是一串字符加回车）。

- **在线输完必须按回车确认**。回车后才向 MES 查询工单；未确认前只是草稿，不会触发查询，也不能在线开工。这样设计是避免半截工单号被打到 MES。**离线开工（本地工单）不要求回车**：离线不查询 MES，直接输入工单号后点「本地工单」即可（`v2.26.2` 修复，此前会误报“未输入工单号”）。
- **回车确认后工单号被固化**（`v2.26.2`）。确认值一旦生效，PLC 寄存器里的常驻值不会再把它顶掉。需要改用扫码时**重新扫一次码**即可——PLC 送来与确认时不同的工单号即视为新扫码，自动解锁并覆盖；PLC 先清空寄存器再写入同一个码也算新扫码。若 PLC 不经清空直接重写同一个值，软件无法与常驻值区分，不会覆盖。操作员再改输入框、清空或该工位开工完成时同样解锁。
- **获取工单信息失败时**（`v2.26.2`）运行状态不再停在「正在获取工单信息...」，而是清空并把 MES 返回的原因（如“工单不存在”）显示在右侧异常摘要；完整原因写入「日志管理 -> 程序异常日志」。
- **生产监控页不再弹出提示窗**（`v2.26.2`）。工单无可选工序、程序列表为空、离线开工缺项、完工数量非法、MES 员工号校验失败、操作异常等提示统一显示在运行状态与右侧异常摘要，不打断值守操作；服务端返回原因时直接显示原因原文。唯一保留的弹窗是产品历史右键「删除」的二次确认。每个中断流程的分支都会把运行状态从「正在...」收尾，避免与异常提示互相矛盾。
- **手动输入期间 PLC 不会覆盖或清空输入框**（`v2.26.2` 修复）。PLC 持续写入工单号数据块且内容不含回车，未扫码时寄存器为空值，此前界面刷新周期会按周期把逐字符输入的内容整段替换或直接清空，导致工单号无法输完。现在只要输入框有焦点，或该工位存有未确认的草稿内容，PLC 值一律不回填、不清空。草稿在**回车确认、输入框被清空、该工位开工完成**后释放，之后 PLC 值照常回填。输入途中切去点别的控件再回来，草稿仍在；切换工位再切回来也不丢。有运行任务时输入框固定显示任务关联工单，不受此保护影响。
- **输入框只读的四种情况**：工位为只读看板（扩展屏）、MES 未连接、当前有运行中的焊接任务、该工位存在未完工任务。此时手输与扫码都不可用；MES 断线需走「本地工单」离线开工流程。
- 工位空闲且操作员未在输入时，PLC 提供的工单号会自动填入并触发查询，用于扫码枪直接接在 PLC 上的现场。

## 开工产品工号与程序名称

一款本地程序可供多个产品工号通用（例如程序里填“通用产品”，而工单工号是 `149#K`），因此自 `v2.27.0` 起产品工号与程序名称是**两个各自独立的录入项**，互不联动、互不回填。

- **在线**：产品工号属于工单信息，只读展示 MES 工单返回的工号，不能改写，也不提供本地程序候选（点击、方向键、回车、打字都不会弹出下拉）。工单没有返回工号时，取到工单即在右侧异常摘要提示“工单未返回产品工号”，点开工再拦一次；请在 MES 中补充后重新获取工单。
- **离线**：产品工号由操作员录入，初始为空、不默认选中，必填；可以下拉选本机程序库中当前工位可生产程序的工号，也可以手输程序库里没有的现场工号。留空点“本地工单”会提示“请输入产品工号”，**不再回退所选程序的工号**。
- **不联动**：选中或改写产品工号不会跳选程序、也不会改动已选程序；选择程序不会回填产品工号；把产品工号清空不会清掉已选程序。程序名称初始为空、不默认选第一项，未选程序就点开工提示必须选择程序。转入离线时产品工号、程序名称、部件图号一起清空——这是“换一批活”的口径，不是联动。
- **部件图号**：在线随工单回填，工单为空则为空。离线初始为空，已填写不会被覆盖；留空时选中程序后用该程序的零组件代码回填。
- **程序列表是否按产品工号收窄**只由“生产监控 -> 按工号筛选”决定。在线按 MES 工单工号筛选（请求形如 `<MES地址>/api/ExpProgram?deviceId=62131399173-2&productNum=115#K-3`，`#` 属于工号本身不做替换，URL 中编码为 `%23`；MES 返回后客户端仍兜底筛选）。离线按界面工号收窄；通用程序场景下手输工号常无匹配程序，此时自动回退到全部程序并提示“该产品工号无匹配程序，已显示全部程序”。未启用时在线离线都显示全部可生产程序。
- **产品工艺与测试项按程序解析**：产品工艺（地址维护 -> 产品工艺）是配在程序里填写的那个工号下的，不是工单工号。实时预览、采集、历史和中心转发都按“程序名称 -> 该程序的产品工号 -> 产品工艺”查找，与开工上报给 MES 的工单工号无关。未选程序时实时预览为空，状态提示“未选择加工程序，无法确定产品工艺”。PLC 配方回读只用于配方号显示与下发核对，不再反查产品身份。
- 已开工、任务运行中或工位只读时上述字段全部只读。
- “工序名称”与其他开工字段同规则：未开工时可编辑（在线态需工单已加载，离线态直接可录入），一旦开工或任务运行中即变为只读。
- 离线模式下“员工号”开放给现场操作员编辑，不预填程序登录账号，也不受“系统设置 -> 操作员弹窗输入”影响；转入离线时会清空在线阶段校验过的员工信息。留空点“本地工单”会提示员工号必填。离线无法向 MES 校验身份，员工号按录入值原样落库和补传，员工姓名、部门和班组保持为空；离线完工沿用开工时录入的员工号，不再二次录入。
- 离线模式下工序号、工序名称和工单数量都不预填默认值，转入离线时一并清空，全部由操作员录入。工序号留空点开工会提示工序号不能为空；工序名称和工单数量允许留空，留空时按空值和 0 落库并上报，任务记录、XLSX 报表表头和生产指标“达成率”会相应显示为空。
- 同一工号存在多个程序时，列表按“程序名称”区分，可继续在程序名称下拉中选择具体程序。
- 双工位分别记忆各自录入的工号；切换工位或退出离线模式时该记忆自动清除。

## 系统设置设备管理锁定

- PLC 设备状态本身不控制“系统设置 -> 设备管理”的可编辑状态；即使 PLC 状态为 `1`，只要当前软件运行态没有活动生产任务，设备管理仍可编辑。
- 任一工位在线或离线开工后，当前运行态存在尚未完工的 `ActiveTask` 时，整个设备管理区域不可编辑；暂停中的活动任务仍保持锁定，完工后自动恢复。
- 数据库中的历史未完工记录不会单独锁定设备管理区域；软件重启后，只有当监控流程把任务恢复为当前运行态任务时才重新锁定。
## 日志管理显示

- 设备状态日志表格不显示“来源”和“工位”，生产流程日志表格不显示“步骤”，设备日志表格不显示“工位”；这些字段仍保留在右侧详情中并继续参与关键字搜索。
- 生产流程摘要统一使用集中维护的中文文本；旧 JSONL 中已存在的配方号调和、设备模式调和和工单状态英文摘要会在界面显示时转换为中文，不重写历史文件。

## MES 在线状态检测

- MES 在线状态由专用的在线检测接口（默认路由 `api/sys`，GET）判定，按系统设置中的「心跳间隔（秒）」轮询，默认 5 秒，可填 1-300 秒；返回状态为 `S` 视为探测成功，连续 3 次探测失败（含超时、非 2xx、响应无法解析）才确认离线，任意一次成功会立即清零失败次数并保持或恢复在线。
- 自动 MES 在线心跳使用独立的 3 秒超时且不写入 MES 交互日志，避免在线探测失败/恢复干扰业务请求排查；连续 3 次失败后的 MES 断线和恢复由设备日志记录。生产模式和上传状态只使用连续失败确认后的连接状态，单次或两次偶发失败不会切换离线。
- 设备校时接口（默认路由 `api/ServerTime`）只在程序启动时调用一次，不再承担在线探测职责。
- 系统设置页的「测试连接」按钮同样访问在线检测接口，因此提示仅显示是否连通，不再返回服务器时间。

## 中心服务器同步与日志

- 设备端按系统设置中的心跳间隔先向中心服务器发送 `heartbeat`。中心服务器不可达时，只记录首次“心跳失败”；持续失败不重复刷日志，恢复连接时再记录一条“心跳成功”。
- 中心服务器连接成功后，设备启动首次同步会发送一次完整 `telemetry`；此后只有 PLC 连接、设备状态、报警、工单、工单数量、产品信息或当日产量等看板字段发生变化时才发送，不再按固定时间重复推送未变化快照。
- 工位快照同时推送工单数量（MES 生产数量）与当日产量，中心看板据此显示「工单数量」和「达成率」。达成率口径为合格数 ÷ 工单数量，与设备端监控页一致，不含不良品，超产时会大于 100%；未选工单或工单数量为 0 时显示 `--`。
- 同一设备两个工位使用同一工单时，工单数量只计一次，避免达成率分母翻倍；两个工位分属不同工单时，工单数量按工单分别累加。
- 断线期间仅保留最新快照。恢复连接后，如果快照相对最后一次成功同步确有变化，会在心跳成功后补发一次；未变化时只恢复心跳，不重复发送设备状态。
- 设备端和中心服务器统一使用三类消息：`heartbeat=心跳`、`telemetry=设备状态`、`product-report=产品数据`。心跳只维护在线时间，设备状态负责更新完整工位快照。

## 生产报表与补传

- “待上传数据 -> 过程参数”页签及工单总览中的过程参数状态只展示、统计目标为 MES 的过程参数；CentralServer 数据仍由其独立后台链路处理，不混入 MES 补传视图。
- 工单完工后本地 XLSX 报表会先生成；只要 XLSX 生成成功，就会进入“待上传数据 -> 报告文件”任务队列并参与 MES 上传/补传，不再依赖产品明细行或 `ReportEnable` 输出项作为入队前置条件。
- 若历史工单已生成 `Biz_ProductionReportFile` 记录但缺少对应 `ReportFile` 上传任务，进入报表待上传页、全部重试或自动补传前会自动补齐任务；用户已经手动删除或已经上传成功的任务不会被恢复。
- 没有任何产品生产数据时，报表仍会按公共字段生成并上传；如果 MES 或文件路径失败，失败信息保留在待上传数据中供手动重试。
- 设备端与中心服务器生产报表统一使用客户参考模板：任务表头依次展示流转卡号/规格/产品型号、产品工号/批次/部件名称、部件图号/工序名称/工序号、工单数量/合格数量/操作人员、程序名称/员工姓名、开始时间/结束时间；明细列按“产品编号 -> 检测面或焊点号 -> 动态测试值 -> 检测结果或焊点结果 -> 产品结果 -> 试焊件”排列。整件检测默认显示“检测面/检测结果”，产品工艺自定义表头仍可覆盖。离线开工除员工号外还必须录入员工姓名，否则报表该栏无从取值。
- 试焊件列自 `v2.25.0` 起写入报表末列，取生产监控页产品历史右键标记的产品级结果：标记过的产品写“是”，未标记留空。该列与 MES 过程参数字段 `IsTest` 共用门禁——关闭系统设置“产品历史显示试焊件”或过程参数设备类型为整件检测时，上传报表、本地导出和看板报表都不输出该列。标记发生在采集完成之后，因此标记或取消标记会自动重推该产品到中心看板刷新该列；已上传、上传中或已跳过的产品仍不允许改标记。
- 已删除产品（见下一节）不进入上传报表、本地导出、数据管理页「测试数据」和中心看板可见页与当日计数；报表明细的产品编号因此可能断号，这是预期行为。

## 产量统计来源与程序计数模式

系统设置「生产配置」分组自 `v2.26.0` 起新增「产量统计来源」，默认 **PLC 计数**（升级后行为不变）。切换为**程序统计**后，以下三件事同时生效，三者绑定不可拆分：

1. **产品编号由程序自算**：每个任务每个工位从 `1` 开始递增，取该任务该工位现有最大编号 +1，形状与 PLC Int16 原值一致，报表编号列外观不变。已删除产品占用的编号不回收。产品工艺里的「产品编号偏移」改为可选；配置了则仍会读取 PLC 编号，但只作整件检测被动重测的比对信号（PLC 触摸屏「重测」不更新编号 → 与上一件 PLC 编号相同 → 覆盖上一件）。
2. **完工三项数量由程序统计**：上报 MES `ExpEnd` 的 `ExpQty / QualifyNumber / FailureNumber` 按本地采集记录计算——总数 = 任务下两工位未删除且已完成采集的产品数（按产品编号去重）；合格 = 产品结果为 OK；不良 = 总数 − 合格（结果未知归不良，保证恒等式）。试焊件照常计入，由报表和过程参数中的试焊件标志区分。同一数字写入 `BizWeldTask.ActualQty/QualifiedQty/FailedQty`，完工补传回退时也同源。程序模式下不再因 PLC 计数读取失败阻止完工，「完工上报实际数量输入弹窗」设置无效；完工时会在程序异常日志写一条 `PLC.FinishQuantity.Compare` 业务记录，同时列出程序值与 PLC 计数器读数供对账。
3. **监控页产量指标同源**：实际数量、合格数量、失效数量和良率改为按同一统计口径显示，达成率分母仍为工单数量。

在程序模式下，生产监控页产品历史右键提供：

- **重焊 / 重测**（整件检测显示为「重测」）：预约该产品为覆盖目标，状态列显示「待重焊/待重测」；下一次 PLC 触发采集时，新数据覆盖该产品（编号、主键、顺序号不变，测试结果与采集时间更新，上传状态打回待上传，试焊件标记保留），覆盖后预约自动清除。同一工位同时只能预约一件，改选其它产品会替换预约；右键「取消重焊/重测」可撤回。软件预约优先于整件检测的 PLC 被动重测信号。
- **删除**：二次确认后软删该产品，行仍显示并标为「已删除」，不再上传、不进报表和产量统计；已入队但未上传成功的过程参数任务置为「已跳过」。右键「撤销删除」可恢复，恢复后按当前上传模式重新入队。
- 以上动作与试焊件共用门禁：产品下任一焊点已上传、上传中或已跳过即不可操作（撤销删除除外）。可操作范围随上传模式自然变化——`Batch` 模式整个任务的产品都未上传，`Quantity` 模式通常只剩最近一两件。删除会写入操作日志（含操作员工号与产品编号），所有可操作监控页的角色均可使用。

限制与升级注意：

- 存在未完工任务时禁止切换「产量统计来源」，需先完工。
- 整件检测设备通常保持 PLC 计数模式；若切到程序模式，PLC 触摸屏重测仍按上述被动信号覆盖，但产品编号以程序为准。
- 中心看板当日计数只统计当天完成的产品，跨天后删除的产品不会从历史日计数中扣除（既有限制）。
- `Biz_WeldPointRecord` 自 `v2.26.0` 起新增自然键唯一索引 `unique_weldpointrecord_naturalkey (TaskId, StationNo, ProductNo, TouchNo)`；升级前请在现场库执行下面的 SQL 确认无重复行，否则启动时 CodeFirst 建索引失败：

```sql
SELECT TaskId, StationNo, ProductNo, TouchNo, COUNT(*) AS Cnt
FROM Biz_WeldPointRecord
GROUP BY TaskId, StationNo, ProductNo, TouchNo
HAVING COUNT(*) > 1;
```

## 产品数据就绪信号卡死兜底

产品采集是一次握手：PLC 置「产品数据就绪 = 1」→ 上位机采集并向「采集完成反馈」写 `1` → PLC 复位就绪为 0 → 上位机把反馈也复位为 0 → 下一件才能再触发。上位机按 0→1 上升沿触发，因此就绪信号必须回到 0。

- **反馈值统一为 `1`**（`v2.26.1` 起）。无论采集成功、采集失败还是程序配置错误，都反馈 `1`，含义只是「本轮已处理完毕，请复位就绪」。此前采集失败反馈 `2`，而现场 PLC 只在收到 `1` 后才清就绪信号，导致 PLC 保持高电平等上位机、上位机等边沿等 PLC，双方互等，一件都采不了，只能重启软件。采集失败与 NG 信息由生产流程日志、监控页异常提示和独立的「产品判定结果」回写地址承载，不再挤进握手信号。
- **5 秒超时强制清零**。就绪信号持续为 1 且超过 5 秒仍无法推进采集时（PLC 未复位、反馈地址配错、PLC 逻辑异常等），上位机主动把就绪信号写 `0` 并同步把采集反馈复位为 `0`，让下一件产品从干净的握手状态重新开始。该兜底在有活动任务和空闲轮询两种情况下都生效。
- **界面与日志可见**。触发兜底时监控页右侧异常摘要显示「产品就绪信号超过5秒未复位，已由上位机清零，请检查PLC采集反馈逻辑」；若连清零也失败（PLC 断线或地址不可写），提示改为清零失败，便于区分两种故障。两种情况都会写入生产流程日志（`ProductDataReadyForceReset`）和业务异常日志，同一轮卡死只提示一次，不会被 200ms 轮询刷屏。
- **地址写入权限**。产品就绪地址正常由 PLC 维护，上位机只在上述超时兜底时写 0，请确认该地址允许上位机写入。

## 上传模式切换的即时生效与副作用

「上传模式」保存后**立即生效**，不需要重启程序：上传协调服务订阅了设置变更事件，下一件产品采集完成时就按新模式处理。三档语义：

| 模式 | 过程参数何时上传 | 生产期间产品上传状态 |
| --- | --- | --- |
| `Realtime` | 每件产品采集完成即传 | 传完即「已上传」 |
| `Quantity` | 凑满「上传批次大小」后，等**下一件**采集完成再传上一批（避开刚采完那一刻）；完工时补传剩余 | 批内产品在下一件到来前保持「待上传」 |
| `Batch` | 全部推迟到完工时一次性补传 | 整个任务期间保持「待上传」 |

切换时需要知道的副作用：

- 切换只影响**之后**采集的产品。任务内已积压的「待上传」产品不会因切换而被主动补传，仍由完工补传兜底（`Batch → Realtime/Quantity` 时尤其明显）。
- `Quantity` 模式的批次载荷在入队时固化，切换批次大小不改变已入队批次。
- 重焊/删除的可操作范围随模式变化：`Batch` 下整个任务可操作，`Realtime` 下几乎只有刚采完、尚未传成功的产品。
- 唯一需要**重启**才生效的配置是 `appsettings.json` 里的数据库连接串；系统设置页的其它配置项都是热生效，其中 PLC IP/端口/类型/心跳/超时保存后会自动重启 PLC 通讯，设备 HTTP 服务地址保存后自动重启该服务。

## 设备状态日志与补传

设备状态固定使用 `0=停机`、`1=开机`、`4=异常`、`5=异常恢复`、`6=程序执行开始`、`7=程序执行结束`。设备状态 JSONL 是唯一事实来源，文件位于配置日志根目录下的 `DeviceStatus/*.jsonl`；日志管理、当前状态查询和待上传数据中的设备状态都从这里读取。

- 状态变化会先写入 JSONL，落盘成功后才会刷新界面、上传 MES 或建立补传任务。
- 待上传数据页签的数据库和 JSONL 查询在后台执行；页签切换复用固定表格列，设备状态读取会复用未变化文件的最新快照，避免重复扫描历史 JSONL。单个损坏记录会被跳过并写入异常日志，不会阻塞页面重绘。
- PLC 报警判定可在“系统设置 -> PLC 配置”选择“仅报警地址”或“设备状态异常且报警地址触发”；旧配置默认使用后者，保存后下一轮采集立即生效。报警读取关闭时冻结当前报警周期，重新启用后再按真实读取结果处理。
- 每个报警地址独立形成“异常触发 -> 异常恢复”链路；多个地址可同轮触发或恢复。部分恢复后会按 `5...5 -> 4` 的顺序重申一个仍有效报警，保证 MES 最终状态仍为异常。共享报警设备级只记录一次（`StationNo=0`），但两个工位监控页都会显示。
- 报警地址属于整台设备，地址维护页不再配置程序工位；历史 `StationNo` 字段仅保留数据库兼容，读取和保存时统一按设备级 `0` 处理。报警内容中的“左/右”等机构描述保持原文，不映射为程序工位。
- MES 与本地 JSONL 的 Remark 使用统一格式：单工位程序边界为 `程序执行开始`/`程序执行结束`，双工位按系统设置映射为 `左工位：程序执行开始`/`右工位：程序执行结束`；异常和恢复统一为 `异常：报警内容`/`异常恢复：报警内容`，不包含报警地址或 PLC 报警工位。设备状态日志表格不显示报警地址和内容，但仍可按这两项搜索并在详情中查看。
- 程序启动时会先把当前 `1=开机` 写入 JSONL，再在后台扫描全部日期文件，按发生时间从旧到新补传 `Pending/Failed` 状态；旧记录上传失败时会暂停本批后续状态，避免新的开机或运行状态越过旧 `0=停机`。该过程不阻塞登录界面。
- MES 断线重连后会复用同一设备状态补传流程，并继续按发生时间顺序处理全部日期 JSONL。
- 关闭窗口时界面立即退出；后台进程会在一个 MES 超时时间内（最少 3 秒，默认 10 秒）同步等待本次 `0=停机` 上报。成功记录为 `Uploaded`，失败记录为 `Failed`，超时前已落盘但未完成的记录保留为 `Pending/Failed`，下次启动继续补传。
- 删除某个日期文件或整个 `DeviceStatus` 目录后，刷新或重新进入日志管理/待上传页面即可移除对应记录；其中未成功上传的状态不再参与单条或批量补传。
- 已成功上传到 MES 的结果不会因为删除本地 JSONL 而撤销，已有上传任务历史也不会回退为待上传。
- JSONL 首次落盘失败时不会上传该状态，也不会生成补传任务。请到“日志管理 -> 程序异常日志”检查磁盘空间、日志目录和写入权限。
- 升级不会删除旧的 `Biz_DeviceStatusLog` 物理表，但程序不再创建、读取或写入该表。


## 程序上下限与严格 JSON（3.0.0）

程序管理和在线下载后的开工确认表格统一为“测试项名称、设定上限、设定下限”。保存/应用前提交当前单元格；非法输入保留并提示具体测试项与限值。

| 设备 | 编辑保存规则 | 判定规则 |
| --- | --- | --- |
| 整件检测 | 下限可空，仅填下限必须补齐上限；上报项在开工前必须有上限 | 上限或上下限比较均包含等号；只允许面数量为 4 的程序投入生产 |
| 电磁/整件点焊 | 两侧空、单侧或双侧均允许 | 限值仅保存并随程序内容上传，不改变 PLC 产品判定 |

填写的限值必须可按固定文化格式解析为 decimal；双侧都有值时下限不得大于上限。编辑时空白侧省略，两侧全空的测试项不写出。完整程序还必须包含正整数“焊点数量”。示例：

```json
{
  "工位1配方名称": "标准配方",
  "焊点数量": "4",
  "高度上限": "12.5",
  "高度下限": "10",
  "对称度上限": "0.5"
}
```

读取接受数字字符串或 JSON 数字，写出统一为字符串。未知但合法的新格式测试项保留；旧的 `"高度":"12.5"`、新旧混用、重复键（含规范化后重名）、非法结构/数字明确拒绝，不转换为空对象。程序中的配方名/工位配方名和焊点数量是保留元数据，不参与判定。

### 旧程序重新配置与任务快照

- 打开纯旧格式程序时先报错，明确选择“重新配置”后才保留原程序身份及有效元数据、展示当前字典的空上下限。旧限值不预填；取消不写库，保存仍生成正常程序版本记录。重复字段或非法结构不能借重配入口忽略。
- 开工确认的“应用本次”只修改本次任务限值，不回写程序库；取消沿用原程序内容，但服务层仍完整校验。开工前校验全部成功，才调用 MES、创建本地任务和排队上传。
- 限值从 `BizWeldTask.ProgramContentSnapshot` 读取；修改程序库不会改变已开工任务限值。工艺按程序绑定的工号而非工单工号解析，双工位共用任务会检查两个工位的上报项。
- 旧或无效快照不能恢复/继续生产、采集、生成正式报告或补传，后台 PLC 工单状态调和也不会放行。历史查看和原始数据导出不转换、重判或改写旧快照。
- 快照只固化程序内容，不固化整套工艺、方案和数值设置；同一任务在配置被修改后重新生成结果不保证历史可重现。生产及待上传期间不要修改相关方案、绑定工号和小数位设置。

## 检测设备四面转 A/B、程序判定与升级检查

`v2.21.0` 重构整件检测的判定口径与数据精度。视觉侧已按新协议改造，客户已确认全部规则。设计依据见 `docs/superpowers/specs/2026-09-05-whole-piece-program-judgement-redesign.md`。

- **为什么要改**：原方案约定视觉检测失败回传 `0`，但对称度真实值可以为 `0`，系统无法区分"未检测成功"与"完全对称"；同时实测值在从 PLC 读出时就按测试项小数位格式化，判定、界面、报表、上传共用同一份已格式化的数值，判定失去对精度的独立控制；视觉改为只回传检测完成信号后，面结果寄存器恒定，逐面判定既无依据也无意义。
- **视觉失败标志改为固定值 `1`**。与现场量程不冲突（高度、宽度不低于 10mm，对称度上限不超过 0.5）。该值写死不做配置：它是与视觉供应商约定的协议值，现场改错会让失败数据被当作合格值参与判定。
- **失败标志按测试项分宽松与严格两种策略**。高度、宽度为宽松项，剔除失败面后用剩余有效值取最大，最少一面有效即可判定（依据规格表注 2"高度不要求全部面都检测"）；对称度为严格项，聚合面内任一面失败即该项判 NG（依据注 3"对称度每个面都需要检测"）。归属按测试项名称固定，新增测试项默认按严格处理。
- **判定精度独立于采集精度**。判定前先按"判定与上报小数位"（默认 2 位）处理聚合值再与上下限比较。截断模式下上限 12.15 的实际允许范围到 12.1599，公差放宽接近一个末位——这是有意的工艺让步，已与客户确认。
- **取消逐面判定**。逐面视图只显示实测值和 PLC 完成信号，不用面结果计算产品合格性；正式报告与过程参数的 A/B 两行使用统一产品结果。本地原始数据及手工导出仍保留逐面采集信息。PLC 仍只回写产品结果。
- **方案明细由五通道改为四通道**。"写入报表"与"过程参数"合并为"上报"，两者对外必然成对生效。勾选"上报"隐含打开"实时预览"与"本地保存"，保证上报项必然出现在逐面视图且本地可追溯，逐面视图的测试项数量始终不少于合并视图。
- **判定范围收紧到"上报"通道**。仅勾选本地保存或转发看板的测试项照常采集留存，但不进合并视图、不上报、不参与判定。由此保证"操作员在合并视图看到的项，就是参与判定的项"。上报项必须填写设定上限，开工前及采集、正式输出入口均校验拦截。
- **A/B 配对聚合固定取最大值**，不再提供"平均值/最大值"配置。原配置存在"新装默认最大值、旧库默认平均值"的分裂，同一产品在不同设备上可能得出不同结果。
- **升级检查**：通道结构与判定范围均已变化且不做自动迁移。升级后须逐项确认方案明细——需对外上报的测试项勾选"上报"通道并填写最大允许值，仅供本地分析的测试项只勾本地通道。所有规则仅对新采集数据生效，已入库的历史数据与已上传 MES 的记录不做追溯修正。

`v2.8.2` 修复“待上传数据”页“处理消息”列中英文混排。该列绑定 `UploadTaskSummary.DisplayMessage`，其值是服务层入库时写死的英文字面量，界面原样渲染；而 MES 超时一类消息来自 `MesProvider` 的本地化调用，是中文，于是同一列出现两种语言。该列被开工信息、完工信息、过程参数、报告文件、工单状态和设备状态六个页签共用（工单信息无消息列；程序文件的“同步消息”由 `ProgramManageService` 写入，本来就是中文，不受影响）。服务层的写入值保持英文不变：这些消息同时充当运维排障线索并会落到上传任务与 JSONL，改存储等于改数据契约，历史库里的旧记录也治不干净。改为在渲染层翻译一次，复刻“上传状态”列既有的 `UploadStatusDisplayRules` 做法，新增 `UploadMessageDisplayRules` 并挂在六个页签共用的 `FormatUploadTaskCell` 上，一处改动覆盖全部页签且历史记录同样显示为中文。收录 21 条固定句，另按前缀翻译 3 条带运行时数据的消息并保留产品编号与产品数；未收录的消息原样透传，MES 返回的 `Msg` 和异常文本不被吞掉。

系统设置的“实时编号来源”（旧称“实时焊点编号来源”）：`PLC读取` 使用产品工艺的 `TouchNoBase/TouchNoExpr`，读取失败显示 `--`，实际数量与预设数量也从 PLC 读取；`程序判断` 完全不读 PLC，编号使用实时预览循环序号 `1、2、3...`，已完成数量按检测结果连续推算（面结果为 OK 或 NG 才算该面完成，中途未完成即停止计数，PLC 残留结果不会让计数跳号），预设数量取当前程序或任务快照的数量，实时预览表格也随之逐面出现，未完成的面不再提前铺满表格。该配置只影响实时预览，不改变正式采集记录、数据管理、中心看板、XLSX 报表或 MES 中的编号，存在未完工任务时禁止切换。

`v2.2.2` 同时修复了产品数据就绪信号的高电平残留处理：PLC在完工后仍保持“产品数据就绪=1”时，上位机不会把旧高电平当作新产品，也不会再次读取已清零的产品号和面号；必须先观察到信号回到0，后续新的0->1上升沿才会触发采集。采集反馈自 `v2.26.1` 起统一为 `1`，只表示“本轮已处理完毕，请PLC复位就绪”，不再用 `2` 表示采集失败——现场 PLC 只在收到 `1` 后才清就绪信号，反馈 `2` 会让双方互等造成采集永久卡死；采集失败与程序判定 NG 的信息由生产流程日志、监控页提示和独立的产品结果回写地址承载。反馈写入失败会在同一就绪周期重试，不会重复采集。就绪信号持续为 1 且超过 5 秒无法推进采集时，上位机会强制把就绪写 0 并复位反馈，同时在监控页提示，详见 [产品数据就绪信号卡死兜底](#产品数据就绪信号卡死兜底)。

`v2.3.0` 起历史显示优先读取采集时固化的产品结果。当前整件检测配置无效时不落本件数据、不生成正式结果，但仍按现行 PLC 协议反馈“已处理” `1`，具体原因记录在生产日志和监控提示中；点焊保持 PLC 产品结果判定。

### 当前 A/B 判定与输出口径

- 整件检测仅允许四面程序执行；A 对应面 2、4，B 对应面 1、3。高度取四面有效值最大值，宽度仅取 A 面有效值最大值；其余测试项按 A/B 配对取最大值，不取平均。
- 先按失败标志 `1` 和宽松/严格项规则筛选，再沿用表达式采集小数位与“判定与上报小数位”处理。上下限均比较这个最终值，边界相等合格。`0` 不是失败标志。
- **下限不是逐面最低值要求**：有效高度为 9、11、下限为 10 时，最大聚合值 11 可以合格。若现场需要每个面都达标，那是另一种判定规则，不属于本功能。
- 仅“上报”实际值项参与判定。A/B 两行的 `Result` 和正式报表“产品结果”统一使用产品判定；任一参与项越界或按失败标志规则未测到有效值时为 NG。
- 格式错误、缺限值、重复项或聚合配置错误是“不可判定”，不是 NG；预览显示原因，采集不落库，报告/上传明确失败，不回退 PLC 面结果。有效配置但数据尚未采齐时仍等待。
- 本地 1～4 面原始记录、数据管理手工导出和中心看板保持原有边界；新增程序上下限不会变成新的 PLC 采集角色，也不会扩展 MES 过程参数字段。

### 部署前检查与回退边界

1. 在旧版完工全部任务，处理 MES 和中心待上传队列并备份现场数据，再部署 3.0.0。没有自动清理、批量迁移或旧格式生产兼容开关。
2. 先联调确认 MES 新增、更新、下载和重试均保留新格式上下限。逐个重填旧程序或从 MES 下载新格式；旧程序库、版本记录和任务快照不自动重写。
3. 核查测试项命名；“高度”“宽度”必须保持既有名称才能使用特殊聚合策略。没有版本标识的扁平 JSON 无法消除历史测试项名本身带“上限/下限”后缀的歧义，这类数据应人工确认来源。
4. 整件检测面数量必须为 4，PLC 面号应唯一覆盖 1、2、3、4；聚合使用按面偏移的相对表达式。为每个上报项填写上限，MES 字段名必须非空且唯一。
5. 验证上下边界、低于下限、高于上限、失败标志、PLC 清零、缺面、双工位及补传；无效任务不得由后台工单状态调和放行。采集反馈 `1` 只表示本轮已处理，不代表 OK，也不自动要求 PLC 重采。
6. 回退版本必须停机并处理当前任务与待上传数据，恢复匹配版本的配置/数据后验证；新格式不能直接交给旧版本，禁止靠切换“检测结果来源”回退。

## 版本管理

软件版本统一配置在 `Directory.Build.props`：

```xml
<Version>3.0.0</Version>
<AssemblyVersion>3.0.0.0</AssemblyVersion>
<FileVersion>3.0.0.0</FileVersion>
<InformationalVersion>3.0.0</InformationalVersion>
```

建议使用语义化版本：

- 主版本：架构或兼容性发生重大变化。
- 次版本：新增功能。
- 修订号：缺陷修复或小范围优化。

版本说明写在两处，内容一致：`CHANGELOG.md` 便于本地搜索和 diff，git tag 便于在 GitHub Releases 页面阅读。README 只保留当前版本号，不堆积历史说明。

发布新版本时：

```powershell
# 1. 改 Directory.Build.props 的四个版本字段，同步 README 当前版本
# 2. 在 CHANGELOG.md 顶部新增该版本条目，写清行为变化和升级注意
# 3. 合并到 main 后打带说明的 tag（-F 从文件读取多行说明）
git checkout main
git merge --no-ff develop -m "release: v3.0.0"
git tag -a v3.0.0 -F tag-notes.txt
git push origin main
git push origin v3.0.0
```

`tag-notes.txt` 为临时文件，内容取自该版本的 CHANGELOG 条目，打完 tag 即可删除。也可用 `git tag -a v3.0.0 -m "标题" -m "正文"` 直接写多段说明。

查看历史版本说明：

```powershell
git tag -n99                # 列出全部 tag 及完整说明
git tag -n99 v3.0.0        # 只看某个版本
git show v3.0.0            # 看 tag 说明 + 指向的提交
```

## 注意事项

- 不要提交本机真实 `appsettings.json`、数据库密码、现场 MES 地址、现场 PLC 地址等敏感配置。
- `bin/`、`obj/`、`.vs/` 为本地构建产物，不需要提交。
- 数据库结构由 CodeFirst 初始化，修改模型后应先在测试库验证。
- 现场联调前应先在系统设置界面确认 MES、PLC、日志路径和设备编号。
